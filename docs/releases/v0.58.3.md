# LinxISA v0.58.3

LinxISA v0.58.3 aligns the v0.58 architecture profile and its maintained
software stack with the published PTO ISA v0.58.3 contract. The release is a
hard compatibility boundary: tools and loaders reject older or mixed PTO
identities instead of silently accepting them.

## Contract identity

- LinxISA profile: `v0.58`
- LinxISA release: `0.58.3`
- PTO release: `0.58.3`
- PTO source commit: `e599a3d36ebfad43362ff591ea5e128816c684c7`
- Encoding ABI: `pto-isa-0.58.3-mode-function-v1`
- Encoding projection SHA-256:
  `8a48b80e04484c70870f155bf9efc79d2a805cf99e809f4e4e8a7e6a7eb34172`
- PTO content SHA-256:
  `f299fe3d256c5d071e57bb4aaa2be2de2e4a386ae090048df1f73ae92d392678`
- Catalog: 466 scalar forms, 74 command forms, 109 Tile operations, and 40
  extension encoding reservations
- Hardware numeric profile: `pto-hardware-numeric-0.58.3-ieee-v1`

The machine-readable authority remains
`isa/v0.58/release_manifest.json` and `isa/v0.58/pto-spec.lock.json`. The
exact reviewed ecosystem commits are recorded in
`docs/bringup/component-lock.v0.58.json`.

## Architecture changes

- Retired `B.EQ`, `B.NE`, `B.LT`, `B.GE`, `B.LTU`, `B.GEU`, `B.Z`, and
  `B.NZ`; their former encodings are reservations, not compatibility aliases.
- Moved `B.IOT` and `B.IOS` to the v0.58.3 `SizeCode` and `PEMode` fields and
  defined mode zero as a strict no-effect path.
- Extended Local and Shared Tile capacity through exact `SizeCode` limits.
- Added `TransA` and `TransB` to `B.FPATR` and updated its decode mask.
- Defined `B.IOR.RegSrc1` as the byte row stride for `TLOAD` and `TSTORE`.
- Added persistent CUBE CELL state, exact input/output layout transport,
  cooperative Shared transpose, and atomic accumulator-output behavior.
- Added VECTOR and CUBE first-use exceptions for lazy context allocation. The
  trap occurs before the block acquires non-recoverable resources or produces
  architectural side effects, and the original instruction is retryable.

The retired generated pages are stored under
`docs/archive/v0.58/retired-pto-0583/` and are explicitly non-normative.

## Ecosystem alignment

- LLVM/LLD emit, preserve, validate, and link the exact v0.58.3 PTO identity;
  MC and CodeGen implement the current scalar, block, Tile, CUBE, and register
  carrier contracts.
- PTOAS consumes the merged LLVM and TileOP surfaces and validates real
  phase-C target compilation and exact-identity links.
- QEMU implements the v0.58.3 decode and execution contracts, including the
  first-use trap, Tile transports, CUBE layout/state, and transactional output
  behavior.
- Linx-TileOP-API exposes the exact v0.58.3 C++ API, target object/link gates,
  and a fail-closed ELF identity parser.
- Linux, glibc, and musl reject missing, malformed, conflicting, old, or mixed
  PTO identities. The maintained C++ runtime build packages compiler-rt,
  libunwind, libc++abi, and libc++ against the exact phase-C sysroot.
- The queue-wired model, PTO kernels, AVS, and agent workflow skill pins are
  updated to the same authority.

## Verification policy

Promotion requires fresh evidence from the exact component lock. Static
coverage, trace-only output, archived reports, stale SHAs, skipped jobs, and
pending jobs do not count as passes. The release train covers ISA/Sail,
LLVM/LLD, PTOAS, QEMU, TileOP, model, Linux/libc, both compile-AVS targets,
target C++ links, and the maintained PTO CUBE workload.

The PTO GitHub release and tag are immutable, but its upstream
`spec/release-manifest.json` still says `specification_status: draft`. LinxISA
records this as metadata debt and aligns to the published v0.58.3 tag without
absorbing v0.58.4 draft work.

## Documentation site

The canonical documentation site is <https://linxisa.github.io/>. Its default
navigation publishes the Chinese manual. The English build remains a strict
validation artifact, and the retired machine-generated `/linx-isa/` site is
not a supported entry point.

# LinxISA v0.58.1

LinxISA v0.58.1 is the reproducible corrective release for the PTO ISA 0.58
transition. It replaces the incomplete component evidence published with the
historical `v0.58` tag without moving or deleting that tag.

## Contract identity

- LinxISA profile: `v0.58`
- PTO release: `0.58.1`
- Encoding ABI: `pto-isa-0.58.1-mode-function-v1`
- Encoding projection SHA-256:
  `89b872d6eaf0252200bc9349d49b9346e2a69d894cdcc2dcd0fd71911c1e0b8c`
- PTO catalog: 474 scalar forms, 74 command forms, and 32 extension
  encoding reservations
- Public PTO tile-operation catalog: 109 operations
- Shared tile binding: 32-bit `B.IOS` with absolute `S0..S255` indices
- Per-PE TSize: codes `1..7` represent 128 B through 8 KiB

The release rejects retired active spellings and identities rather than
silently accepting mixed v0.57/v0.58 objects.

The common subset adds `B.FPATR`, fused `BSTART.CALL`, fused
`BSTART.ICALL`, and `L.BSTOP`; removes the four obsolete FP/STD CALL/ICALL
spellings; and preserves every Linx-only two-level form only where the PTO
reservation catalog covers its complete encoding.

## Corrected integration

- LLVM, PTOAS, QEMU, Linux, glibc, and musl use one byte-identical
  `.note.pto.isa` identity and fail closed on missing, old, malformed,
  conflicting, or mixed identities.
- Linx-TileOP-API and the maintained nested SuperNPU workload use the active
  Shared TMOV, allocation-mask, and per-PE TSize contracts.
- The architectural model, pyCircuit, and LinxCore consume the same generated
  v0.58 catalog and expose the same Shared allocation/effect rules.
- QEMU includes strict metadata and runtime coverage for the four Shared TMOV
  selectors.
- The component lock records merged, reviewable leaf commits. The
  LinxCoreModel candidate remains explicitly review-only in its open pull
  request and is not presented as a released component.

## Reproducibility

Release assets contain the generated ISA manual, public catalog, exact
component lock, current gate evidence, leaf provenance, and checksums. The
immutable `v0.58.1` release tag is the integration identity.

`PTO-ISA/SuperNPUBench` is retained only as an issue-tracking surface. The
release does not push code, create a tag, or publish a release in that removed
standalone repository; maintained workload evidence comes from
`workloads/pto_kernels/benchmarks/supernpu`.

# LinxISA 0.59.1 specification · revision 1

Revision 1 defines the LinxISA 0.59.1 architecture specification, binary encodings, and hardened Sail package described on this page. Select profile `v0.59` explicitly. The machine-readable identity is owned by `isa/v0.59/release_manifest.json`, the compiled catalog, and the exported Sail package—not by a release-page title alone.

The signed specification baseline is commit `d262515b55c727073997c8f4c95261909f2fe8d3`. Revision 1 retains the version identity `0.59.1` while changing the active catalog. Treat the baseline commit as provenance and use the manifest revision plus content digests to identify the revised specification; do not infer the revision from a tag name or hosting location.

## Identify revision 1

A source tree or release asset represents this revision when the manifest declares version `0.59.1`, revision `1`, and the catalog bytes match the manifest digest. Read the digest from the manifest; do not duplicate it in prose.

```sh
python3 - <<'PY'
import hashlib, json
from pathlib import Path

manifest = json.loads(Path("isa/v0.59/release_manifest.json").read_text())
catalog = Path(manifest["catalog"]["path"])
digest = hashlib.sha256(catalog.read_bytes()).hexdigest()
assert manifest["publication"]["version"] == "0.59.1"
assert manifest["publication"]["revision"] == 1
assert digest == manifest["catalog"]["sha256"]
print(manifest["publication"]["version"], manifest["publication"]["revision"], digest)
PY
```

## Revised specification scope

The revised catalog contains **1,306 instruction forms under 561 catalog mnemonic names in eight instruction classes**:

| Inventory | Forms |
| --- | ---: |
| Unqualified common scalar forms | 473 |
| Common command forms | 105 |
| Linx-only forms | 23 |
| Scoped 64-bit forms | 705 |
| **Total** | **1,306** |

The 23 Linx-only forms comprise 19 retained definitions and four encoding-only forms: `DMA.FREE.L`, `DMA.FREE.S`, `MCOPY.DL`, and `MCOPY.DS`. The four encoding-only forms are not implemented and must reject before operand reads or architectural effects.

This revision removes 193 former active forms: all 184 `V.*` forms plus nine two-level block entry/body forms. PTO-SPEC continues to own their complete encoding spaces through **10 reservation records**—one wildcard `V.*` region and nine named reservations. Matching instructions hard-reject; there is no compatibility decoder and the encodings remain unavailable for reallocation. This does not remove the PTO Tile VEC engine, the `BSTART.TEPL` carrier, or Tile operations such as `TADD`. [Architecture decision](../architecture/linx-two-level-block-obsolescence.md) · Working catalog: `isa/v0.59/linxisa-v0.59.json`

The profile separately carries 119 direct Tile operations, 100 system-register definitions, and 50 PTO extension-space reservation records. The upstream dependency remains PTO `v0.59.1.0` at commit `a89a53d48f5708328be609fe2e6296ac8bdb4bc2`. The 578 common forms and 705 scoped forms retain their PTO ownership. The source lock is `isa/v0.59/pto-spec.lock.json`.

The ELF identity remains release `0.59.1`, ABI `pto-isa-0.59.1-mode-function-v1`, and encoding projection SHA-256 `d90c881754d66f2cd26f6014d0b582cba88307e70123583d87fc59a918229c28`. Keeping that identity does not imply that the original signed tag already contains this revision.

## Dedicated Sail source and reproducible checks

The revision-specific Sail source is under `isa/v0.59/sail/`. The v0.59.1 exporter assembles the versioned state and execute sources with the shared modules, generates the decoder from the current 1,306-form catalog, and writes the explicit rejection paths for the reserved encoding ranges. The self-contained package includes a file manifest and checksums. Do not substitute the generic development model for this versioned export. Use Sail 0.20.2 for the parser, directed tests, and C backend checks.

```sh
python3 tools/isa/select_linxisa_profile.py --profile v0.59
python3 tools/isa/build_golden.py --profile v0.59 --check
python3 tools/isa/validate_spec.py --profile v0.59
python3 tools/isa/check_pto_v0591_alignment.py
python3 tools/isa/check_v0591_candidate_dispatch_sail.py
python3 tools/isa/export_linxisa_v0591_sail.py --output /tmp/linxisa-0591-sail
python3 tools/isa/export_linxisa_v0591_sail.py --check /tmp/linxisa-0591-sail
```

## System-validation gaps

Specification/catalog/Sail consistency does not qualify a chip or platform. The following system surfaces remain outside the specification-level evidence:

| Surface | Current evidence and required work |
| --- | --- |
| Compiler and emulator | Earlier 0.59.1 work sampled 71 executed forms and compared 180 scoped carriers and 1,440 result bytes across QEMU, linx-model, gfrun, and gfsim. That evidence is neither exhaustive nor a clean rerun of this 1,306-form revision. LLVM active-replay lowering still needs a legal branch-free implementation, and compiler/QEMU coverage must prove that removed encodings are rejected rather than translated. [AVS](https://github.com/LinxISA/linx-isa/pull/239) · [LLVM](https://github.com/LinxISA/llvm-project/pull/182) |
| LinxCore RTL | Candidate opcode parity and stage connectivity passed, but runner/cosimulation stopped in the pyCircuit JIT at the historical `Wire._zext` API. RTL execution parity and hard rejection of all ten reserved ranges remain unqualified. [LinxCore](https://github.com/LinxISA/LinxCore/pull/55) |
| Linux | Earlier initramfs smoke/full boot and a diagnostic BusyBox block-rootfs boot passed on earlier component pins. Rebuild and rerun on the final compiler, emulator, kernel, rootfs, and revised specification pins are still required. [Linux](https://github.com/LinxISA/linux/pull/36) |
| Integrated system | Final component pins, both required runtime-convergence lanes, complete downstream decode removal, and full-system qualification remain open. A full-system pass is not part of the specification-revision evidence. [Component pins](https://github.com/LinxISA/linx-isa/pull/230) · [System qualification](https://github.com/LinxISA/linx-isa/pull/237) |

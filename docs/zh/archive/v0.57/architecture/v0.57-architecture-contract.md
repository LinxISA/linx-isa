# 灵犀指令集 v0.57 架构合约

> 历史、非规范归档。不得将本页用于当前 ISA 或实现决策。

本文档定义 LinxISA v0.57 的实时公共架构合约。v0.57 是唯一维护的 ISA
配置，整合了完整标量、向量、tile、系统、内核执行和渲染合约以及本版本
编码新增项。

## 范围

- 活动 ISA：`v0.57`
- 规范目录：`isa/v0.57/linxisa-v0.57.json`
- 规范黄金源：`isa/v0.57/`
- 内核执行状态：`isa/v0.57/state/kernel_execution.json`
- 渲染配置：`isa/v0.57/state/rendering_profile.json`
- v0.57 PTO 选择子清单：
  `isa/v0.57/state/pto_encoding_map.json`

v0.57 是无遗留兼容面的活动合约。已删除的兼容拼写、历史原始片段、
混合通用文本形式和迁移垫片仍然非法，除非 v0.57 清单将其显式定义为
规范形式。

## 规范规则

v0.57 的机器可读目录和状态文件是规范来源：

1. [v0.57 编码决策](v0.57-encoding-decisions.md)列出的 TMA 选择子。
2. v0.57 opcode 源文件中的标量编码。
3. `isa/v0.57/state/pto_encoding_map.json` 中冻结的 PTO tile 操作选择子。
4. 与这些规范保持一致的文档和下游实现。

编译器、模拟器、Linux、RTL 和模型不得从草稿表格、归档设计说明或旧示例
推断额外的 v0.57 语义。v0.57 操作若不在机器可读清单中，就不属于活动 ISA
合约。

## TMA Function 分配

TMA function 字段仍使用现有 tile-memory 块头中的 5 位 `Function`：

`31..27=DataType`，`26..25=00`，`24..20=Function`，
`19..15=00010`，`14..0` 为固定块分割尾部。

tile-memory 别名占用连续 function 槽位：

| Function | 规范别名 | v0.57 状态 |
|---:|---|---|
| 0 | `BSTART.TLOAD` | load |
| 1 | `BSTART.TSTORE` | store |
| 2 | `BSTART.TMOV` | tile move |
| 3 | `BSTART.TPREFETCH` | v0.57 新选择子 |
| 4 | `BSTART.MGATHER` | v0.57 新选择子 |
| 5 | `BSTART.MSCATTER` | v0.57 新选择子 |
| 6 | `BSTART.MGATHER.MASK` | v0.57 新选择子 |
| 7 | `BSTART.MSCATTER.MASK` | v0.57 新选择子 |
| 8 | `BSTART.MGATHER.CAS` | v0.57 新选择子 |
| 9..31 | 保留 | 非法，除非后续 v0.57 清单显式分配 |

通用或混合文本形式（例如 `BSTART.TMA <op>, <DataType>`）在规范 v0.57
源中仍然非法。合法公开拼写是已分配 function 的规范别名。

## `BSTART.TPREFETCH`

`BSTART.TPREFETCH` 分配给 TMA `Function=3`，紧邻 `TLOAD`、`TSTORE`
和 `TMOV`。

`TPREFETCH` 与 `TLOAD` 具有相同的地址生成、描述符校验、地址翻译、
权限检查、内存异常、顺序和可重启合约，但移除所有目的端效果：

- 无 B.IOT 目的绑定，
- 无 tile 分配，
- 无 tile 队列 push，
- 无 tile 元数据或数据写回，
- 无架构目的依赖。

`TPREFETCH` 不是可忽略的提示。实现可以选择任意微架构缓存动作，但必须对
同一 footprint 执行与 `TLOAD` 相同的架构地址检查和异常行为。异常
`TPREFETCH` 与异常 `TLOAD` 一样精确且可重启。非异常 `TPREFETCH` 完成后不产生
可见寄存器或 tile 结果。

## PTO tile 操作边界

已检入 PTO 清单对工作簿全部 111 行进行了唯一分类：97 行使用 TEPL
选择子，6 行使用 TMA function，8 行使用 CUBE function。
`isa/v0.57/state/pto_ops.json` 保留工作簿操作数、dtype、说明、目标支持和
证据；`pto_encoding_map.json` 是规范的 Linx 编码归属。

- `MGATHER`、`MSCATTER`、`MGATHER.MASK`、`MSCATTER.MASK` 使用现有
  tile-block 文档中的 gather/scatter 描述。
- `MGATHER.CAS` 是 PR #133 定义的 v0.57 逐元素原子 gather 选择子。每个
  活动 lane 返回 CAS 前的内存值；比较失败可通过该返回值观察，软件可以重试。
- 已有选择子的 PTO 拼写保持原选择子。`TTRANS` 映射到规范
  `TTRANSPOSE`；仅在评审材料出现的名称和拼写错误不属于架构。
- 新选择子只占用 `0x02B..0x048`、`0x080..0x08B`、
  `0x0C0..0x0C8` 和 `0x0E0..0x0E3`。

## 标量 CAS 和 DMA 边界

v0.57 增加 LinxISA/linx-isa#139 定义的 32 位 `CASB`、`CASH`、`CASW`
和 `CASD` 编码。它们原子读取 `[SrcL]`，将旧值与 `SrcR` 比较，在相等时
写入 `SrcD`，并将旧值返回 `RegDst`。这些形式支持 `aq` 和 `rl` 排序，不
支持 `far`；原有 48 位 `HL.CAS*` 形式保持不变。

v0.57 还分配该 PR 中的 32 位 `DMA` 编码：`SrcL` 保存源地址，`SrcR` 保存目的地址，固定
复制 64 字节，并在提交命令前完成。PR 临时说明中的“控制参数”不构成新的
控制字 ABI，不得据此重新解释 `SrcR`。

## 提升前闭环要求

v0.57 完成前必须满足：

- `isa/v0.57/state/engine_ops.json` 标识 `v0.57` profile，并列出上述合法
  TMA 别名。
- `isa/v0.57/state/pto_encoding_map.json` 冻结完整 PTO 选择子映射。
- v0.57 JSON、opcode、手册、Sail、编译器、模拟器、Linux、RTL 和模型投影
  对 mask/match 和合法性规则一致。
- 负向测试拒绝未分配 TMA function、已退休兼容拼写和通用混合文本形式。
- 下游测试证明 `TPREFETCH` 像 `TLOAD` 一样异常和排序，但不产生目的端效果。

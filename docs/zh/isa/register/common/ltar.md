# LTAR

LTAR（Local Tile Address Register）称为Tile形参寄存器，是分离块（Decoupled Block）中用于与调用方进行大块数据（Tile）级通信的核心机制，支持高效、结构化的输入输出传递。

## 寄存器定义

每个可读写Tile寄存器的块指令支持：

- 8个输入Tile寄存器
- 4个输出Tile寄存器
- 1个栈空间Tile寄存器（S-Tile）

为满足数据交互需求，分离块内部定义了 **14个Tile类型形参寄存器**，用于映射调用方传入的Tile寄存器。

Tile形参寄存器列表如下：

| 寄存器 | 类型 | 说明 |
|--------|------|-----|
| TA | 输入 | 存储本块的 第一个输入Tile寄存器的首地址 |
| TB | 输入 | 存储本块的 第二个输入Tile寄存器的首地址 |
| TC | 输入 | 存储本块的 第三个输入Tile寄存器的首地址 |
| TD | 输入 | 存储本块的 第四个输入Tile寄存器的首地址 |
| TE | 输入 | 存储本块的 第五个输入Tile寄存器的首地址 |
| TF | 输入 | 存储本块的 第六个输入Tile寄存器的首地址 |
| TG | 输入 | 存储本块的 第七个输入Tile寄存器的首地址 |
| TH | 输入 | 存储本块的 第八个输入Tile寄存器的首地址 |
| TO | 输出 | 存储本块的 第一个输出Tile寄存器的首地址 |
| TO1 | 输出 | 存储本块的 第二个输出Tile寄存器的首地址 |
| TO2 | 输出 | 存储本块的 第三个输出Tile寄存器的首地址 |
| TO3 | 输出 | 存储本块的 第四个输出Tile寄存器的首地址 |
| TS | 栈 | 存储本块的 栈空间Tile寄存器（S-Tile）的首地址 |
| TP | 持久化 | 存储本块的 持久化Tile寄存器（[PT](./PT.md)）的首地址 |

## 映射机制

Tile形参寄存器通过块头指令 [B.IOT](../../header/B.IOT.md) 与调用方传入的 Tile 寄存器进行绑定。硬件按 B.IOT 序列中操作数的出现次序，将各 Tile 首地址逐一填入对应的形参寄存器。

- **输入映射**（TA ~ TH）：
    - TA -> 第1个输入Tile寄存器
    - TB -> 第2个输入Tile寄存器
    - ...
    - TH -> 第8个输入Tile寄存器
- **输出映射**（TO ~ TO3）：
    - TO  -> 第1个输出Tile寄存器
    - TO1 -> 第2个输出Tile寄存器
    - TO2 -> 第3个输出Tile寄存器
    - TO3 -> 第4个输出Tile寄存器
- **栈空间映射**（TS）：
    - TS  -> 栈空间Tile寄存器（S-Tile）
- **持久化Tile映射**（TP）：
    - TP  -> 持久化Tile寄存器（[PT](./PT.md)），由独立的 `B.IOT [xx], ->PT<Size>` 在 Tile 容量池中分配，非由调用方传入

TS 与输出形参寄存器（TO~TO3）独立，不共用槽位。无论块指令有无输出、输出数量多少，S-Tile 始终映射至独立的 TS 形参寄存器。

映射为运行时动态绑定，同一块指令的不同调用方可传入不同的 Tile 寄存器组合。

## 汇编示例

汇编示例如下：
```asm
Header:
    MPAR .Body <LB0:64, LB1:32> T#1, U#1, T#2, [a0], ->M<256B>
    ...
Body:
    l.lw  [TA, LC0.uh<<2],   ->vt.w       # TA映射到块头的T#1输入
    l.lw  [TB, LC0.uh<<2],   ->vt.w       # TB映射到块头的U#1输入
    l.add vt#1.sw, vt#2.sw,  ->vt.w
    l.sw  vt#1.sw, [TO, LC0<<2]           # TO映射到块头的M输出
    l.ld  [TC, LC0.uh<<3],   ->vt.d       # TC映射到块头的T#2输入
    l.sd  vt#1.ud, [ri0.ud, LC0<<3]
    bstop
```

## 关键规则与注意事项

**1.初始值来源**

- Tile形参寄存器（TA/TO等）的初始值由调用方硬件在解析块头时分配，不可在块内修改。
- 若块内尝试读取未初始化的形参寄存器（如未传入的 ），结果为未定义。

**2.映射空间读写权限**

| 寄存器类型 | 权限 | 说明 |
|-----------|--------|-------|
| 输入形参映射空间（TA、TB等） | 只读 | 块内读取合法；写入触发非法指令异常 |
| 输出形参映射空间（TO、TO1、TO2、TO3） | 可读写 | 若读取未写入的位置，结果为未定义（undefined）；写入后读取结果为写入值 |
| 栈形参映射空间（TS） | 可读写 | 用于块内栈空间的读写操作；若读取未写入的位置，结果为未定义（undefined） |
| 持久化形参映射空间（TP） | 可读写 | 用于块内访问持久化Tile（PT）的数据空间；若 PT 未被分配则该值为未定义，访问可能触发异常 |

安全设计：禁止写入输入寄存器，防止数据污染与状态错误。

## 应用场景

1. **向量数据处理**：批量读取输入Tile，批量写入输出Tile。
2. **模块化函数调用**：不同调用者传入不同数据源。
3. **栈空间集成**：输出Tile寄存器可用于临时存储（如函数调用栈）。

## 总结

Tile形参寄存器为分离块提供了结构化、高效、安全的Tile级数据接口。通过最多8个输入、4个输出、1个栈空间与1个持久化Tile寄存器，共14个形参，支持灵活的模块间通信。栈空间形参TS与输出形参完全独立，避免了共用槽位带来的映射冲突。TP 用于映射跨块持久化的 PT 寄存器，其分配与释放由外部块通过 B.IOT 管理。

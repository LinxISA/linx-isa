# V.LD.MIN

## 说明

逐活动的 64 位元素执行有符号最小值读改写。`SrcL` 只给出一个内存地址。发布 Sail 按元素递增顺序处理活动元素：读取该地址的旧值，与当前 `SrcR` 元素按二进制补码有符号数比较，将较小者写回同一地址，并把本次读取到的旧值写入对应目的元素。多个活动元素会连续更新同一个内存单元，后面的元素看到前面元素写回的值。

可选的 `aq`、`rl` 和 `f` 后缀由对应编码位承载，但 v0.59.1 发布 Sail 的当前处理程序不使用这三个值。处理程序以显式的加载和存储描述读改写，没有给出并发观察者之间的原子互斥规则。目的寄存器得到的是每一步的内存旧值，而不是最终写回的最小值。P 掩码为 0 的元素不访问内存，并保持目的寄存器中的原值。

## 汇编语法

```asm
v.ld.min<.{aq, rl, f, aqrl, aqf, rlf, aqrlf}> [SrcL], SrcR, ->Dst
```

## 例子

内存旧值为 7、`SrcR` 为 2 时，执行后内存为 2，目的元素得到 7。内存旧值为 -3、`SrcR` 为 5 时，内存仍为 -3，目的元素得到 -3。

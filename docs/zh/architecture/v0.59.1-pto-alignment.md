# LinxISA 同步 PTO 0.59.1

LinxISA 的 `v0.59` 候选通过 `isa/v0.59/pto-spec.lock.json` 锁定已发布的 PTO 指令集架构
`v0.59.1.0`。源提交为 `a89a53d48f5708328be609fe2e6296ac8bdb4bc2`，编码 ABI 为
`pto-isa-0.59.1-mode-function-v1`。候选验证期间，当前 superproject 和组件 pin 仍遵循
[LinxISA v0.58 架构合约](v0.58-architecture-contract.md)。
[PTO 发布与签名标签](https://github.com/PTO-ISA/pto-spec/releases/tag/v0.59.1.0)

## 编码变化

同步内容含 473 个无 scope 的 Scalar 表单、705 个带 scope 的 Scalar 表单、105 个命令表单、
119 个直接 Tile 操作、50 个扩展编码保留项和 100 个系统寄存器定义。使用
`tools/isa/import_pto_v0591.py` 从锁定的源码检出重建。

生成的 `isa/v0.59/pto-v0591-candidate.json` 记录待评审的公共表单投影和 scoped 解码合约。
运行 `python3 tools/isa/build_pto_v0591_candidate.py --check` 可核对该快照。

已有的 578 个 Scalar 和命令表单保留有效 mask/match、拼写和操作数字段布局。上游发布的
`B.DATR` 增加 `CMode` 值 6 和 7，`BSTART.TMOV` 增加原始 `DataType` 值 15 和 21。
新增的 705 个 64 位载体与现有的 194 个 Linx 64 位表单在编码空间中没有重叠。对齐检查逐项
比较源表单 ID、有效编码、操作数字段、约束域和保留项。
[PTO 兼容性边界](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/docs/status/decisions/ADR-GOV-0015-0590-0-to-0591-compatibility.md)

## Sail 与启动寄存器

现行 Linx 寄存器合约把 `0x0050`、`0x0051` 分别分配给只读的 `BLOCKNUM` 和 `BLOCKID`。
Sail 使用这份地址映射，环境值复位为零。块内维度仍由现有 Block 指令选择和维护，旧别名地址
`0x0052` 至 `0x0055` 保留。

PTO 发布的启动协议在 LAUNCH 接纳后向目标 ACR0 worker 提供独立的逻辑几何，直到匹配的 DONE
或 invocation 清理。Sail 已建模消息缓冲区 bank、认领和 ACK、BSE 接纳与重放，以及
READY/LAUNCH/DONE。定向测试在绑定的平台上下文中执行编码后的 SSR 和 BSE/BWE。嵌入平台
负责提供当前 invocation 和恢复状态。

705 个 scoped Scalar 载体都经过 Sail 的请求与完成流程。模型捕获 scope 和外层 TPC，保留受阻
请求，遇到异常时丢弃待提交的效果，成功时按八字节退休。平台负责内存排序、双访问预检、原子
效果、保留状态，以及与其他指令路径的队列同步。
[PTO HSCB 启动合约](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/arch/state/hscb-dispatch.asl)
· [PTO scoped Scalar 合约](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/scalar/model/dispatch/top-level.asl)

## Scoped Scalar 参考模型对照

使用支持 PTO 0.59.1 候选开关的 LLVM、LLD、QEMU 和 linx-model 构建产物运行内存对照。

```bash
python3 tools/bringup/check_pto_v0591_scalar_reference.py \
  --llvm-bin "$LLVM_BUILD/bin" \
  --qemu "$QEMU_BUILD/qemu-system-linx64" \
  --linx-model "$LINX_MODEL_BUILD/linx_model_cli" \
  --gfrun "$LINX_CORE_MODEL/bin/gfrun" \
  --gfsim "$LINX_CORE_MODEL/bin/gfsim" \
  --output out/pto-v0591-scalar-reference
```

脚本校验 ELF 标识，并将同一份 ELF 交给单 PE QEMU、linx-model 参考执行器和指定的
LinxCoreModel 二进制。每个模型都必须到达成功 finisher，并导出 180 个 immediate/PCR
载体的 1,440 字节结果。脚本分别与依据锁定目录独立生成的期望值比较，再对模型结果做两两
比较。省略 `--gfrun` 和 `--gfsim` 可运行双模型诊断。启用 `--symbolic-pcr` 后，脚本检查汇编器
生成的 66 条 PCR 重定位都指向各自的 64 位载体起点。LLD 写入内层 PCR 字段，四模型沿用同一份
期望结果。`provenance.json` 记录二进制与 ELF
哈希及源码提交。`compare.json` 记录执行失败和第一个不一致的表单。发布资格还需要多核执行、
MSGB/HSCB 主机集成和锁定的 LinxCoreModel 检查。

## Superproject 发布证据

发布 LinxISA `v0.59.1` 需要由新 profile 驱动解码器和文档生成，在固定版本的 Sail parser 和 C
backend 上获得执行验证，并通过精确兼容的组件 pin 验证。组件合入提交及验证证据应与
superproject gitlink 一起记录。PTO 发布验证证明上游输入，对齐检查证明其与现行 Linx 编码目录的
静态匹配。

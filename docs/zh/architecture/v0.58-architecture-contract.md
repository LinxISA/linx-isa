# LinxISA v0.58 架构合约

本分支以 `pto-scalar-proposal.lock.json` 锁定公共指令目录，并以独立的
`pto-runtime-startup.lock.json` 绑定启动 ABI 语义。机器可读权威来源是
`isa/v0.58/linxisa-v0.58.json` 以及 `isa/v0.58/` 下的状态和发布文件。

公共的标量、块和 Tile 指令必须与 PTO ISA 0.58 保持一致；LinxISA
额外保留两级向量架构。PTO 会保留这些 Linx-only 编码空间，但不会定义
其语义。当前工具链不得接受已经删除的旧助记符，也不得从历史 profile
推导当前编码。

公共子集包含 473 条 scalar form、105 条 command form 和 119 条 Tile
操作，以及 50 个占用的 extension encoding reservation；当前目录是未出版的开发版本。

每个块局部维度寄存器 `LB0`、`LB1` 和 `LB2` 在该块省略对应的 `B.DIM`
或 `C.B.DIMI` 写入时，其有效值均为 1。包括零在内的显式写入会替代该
默认值。维度 presence 只用于拒绝重复写入和陷阱恢复；操作合法性与执行
不得区分“省略”和“显式值 1”，也不得从 Tile descriptor 推导省略的维度。
因此工具链会省略解析后值为 1 的维度指令。

119 条 Tile 操作的执行单元严格分为 `32 VEC / 47 SFU / 28 TLSU /
12 CUBE`。VEC 只执行逐元素运算；复杂函数、归约/展开、重排和不规则
运算由 SFU 执行。TEPL 不是执行单元，而是 VEC/SFU 保持不变的
Mode/Function 编码载体。`BSTART.TEPL` 是唯一编译后的译码身份，汇编器
接受 `BSTART.VEC` 与 `BSTART.SFU` 别名，规范反汇编按目录中的执行单元
选择别名。这些别名不占用新编码空间。

七个规范语义类别的数量为：26 elementwise-tile-tile、16
tile-scalar-and-immediate、28 reduce-and-expand、27
memory-and-data-movement、12 matrix-and-matrix-vector、6
layout-and-rearrangement、4 irregular-and-complex。

TLSU 新增 GM exchange、min/max、add、increment/decrement、bitwise 和
population-count 变体。`BSTART.TIMG2COL` 使用 TLSU Function 28；旧的直接
`TIMG2COL` Tile 操作保持退役。`TCONCAT`、`TEXTRACT`、`TINSERT`、
`THISTOGRAM`、`TQUANT`、`TDEQUANT`、`TSORT` 和 `TMRGSORT` 不提供兼容别名。

Shared Tile 寄存器是每个 core 私有的 `S0` 到 `S63` 绝对索引寄存器组，
由该 core 的四个 PE 共享。Local 和 Shared 使用四位 `SizeCode`；三位
`PEMode` 通过固定表译码为四 PE mask，零 mode 是所有后续检查之前的
严格无副作用路径。B.IOT 的目的容量代码 1..10 表示 128 B..64 KiB，
B.IOS 的目的容量代码 1..12 表示整个 core-wide Shared 对象的
128 B..256 KiB。

TLOAD/TSTORE 使用 `B.IOR.RegSrc0` 表达 GM base，使用
`B.IOR.RegSrc1` 表达按字节计数的 row stride。每个参与 PE 从自己的
GPR 文件解析相同的绝对寄存器选择器。
索引 TLSU 操作的 `RegSrc1` 必须为零，索引 Tile 直接提供按字节计数的 GM displacement，
不会改变仅供 Linx vector body 使用的 repeated `B.IOR` 规则。

英文 `docs/architecture/v0.58-architecture-contract.md` 是本页的规范叙述
来源；本中文页为辅助说明。

## 四 PE runtime 启动 ABI

`isa/v0.58/pto-runtime-startup.lock.json` 单独绑定软件启动 ABI；编译目录的
`state.pto_runtime_startup` 从 PTO 精确提交
`2209562859a89be80b73ea926f5d60b9d018faae` 投影六个 NDF 条款。该绑定接纳
PTO PR #415 的启动决策，与现有标量/目录锁并存，不替换目录锁，也不改变编码或出版
身份。使用 `tools/isa/pto_runtime_startup.py` 从冻结的上游 Git 对象重新生成并校验。

四个独立 PE context 从共同入口进入，PE0 负责共享初始化，worker 完成必要私有准备后
与 PE0 在同一 generation-zero `SYNC.CORE` 会合；释放后进入工作阶段。精确启动顺序、
GM 顺序、恢复、失败和重新 launch 规则归导入条款所有。进程级构造与每次 invocation
准备具有不同生命周期；屏障不能创建尚未启动的 PE context。

标准只读 `THREAD_ID` 使用 SSR `0x0026`，返回执行 PE 的 `0..3` 身份，区别于 OS
线程、Core、向量 lane 及 Linx group/lane 计数器；按继承契约在合法 SYS Block 中
使用 SSRGET 或 HL.SSRGET。此绑定不分配历史地址 `0x0802`。

### 下游适配要求

| 组件 | 必须完成的适配及证据 |
| --- | --- |
| LLVM/compiler-rt、linker | 共同入口、合法身份/屏障 lowering、单次共享初始化与内存顺序；提供反汇编和精确版本。 |
| musl/glibc、runtime | 独立 live stack 与私有 bootstrap、PE0 共享/进程初始化归属、明确 TLS/service 权限；验证重复 launch 和致命初始化失败。 |
| Linux、平台/固件 loader | 四个真实 PE context、entry/参数/栈绑定、invocation 身份及完成/异常/abort/reset 接口；仅创建 SMP/pthread 不足以证明满足契约。 |
| QEMU、ASL-Model、LinxCoreModel、RTL | 独立 context、真实到达与等待；验证两种到达顺序、缺参与者、失败和同入口重新 launch 隔离。 |
| TileOP、工作负载 | 四 PE launch 遵循本启动契约，保留 single-context 保护；跨模型使用同一 ELF 和绑定，配合独立 golden。 |

每个组件在声明支持前须记录实现 PR、合并版本及共同入口 runtime-only ELF 结果，
证明四个身份、独立栈、单次共享初始化与数据可见性。本次规范更新不推进组件 pin。

当前 Sail 仍为单上下文：`SYNC.CORE` 仅支持 decode，`THREAD_ID` 尚无执行实现；
导入契约不代表四 PE launcher/runtime 已完成。具体 ELF 标识、参数/栈/TLS 布局、
launch 传输及完整 fd/syscall/exit ABI 继续由
[PTO #150](https://github.com/PTO-ISA/pto-spec/issues/150)、
[PTO #386](https://github.com/PTO-ISA/pto-spec/issues/386) 跟踪。

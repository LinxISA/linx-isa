# LinxISA 0.59.1 规范修订

当前工作树正在准备 LinxISA 0.59.1 架构规范、二进制编码和强化 Sail 包的第 1 次修订。它仍是 **尚未发布的工作规范**：修订后的 tag、GitHub Release 和离线手册均未上传。芯片设计查阅本版时应显式选择 `v0.59`；整机 bring-up 的默认 profile 仍为 `v0.58`。机器可读来源为 `isa/v0.59/release_manifest.json` 和 `isa/profile-selection.json`。

现有签名标签 `v0.59.1` 指向提交 `d262515b55c727073997c8f4c95261909f2fe8d3`，代表最初发布版本。该标签仍包含旧的 1,499 形式目录，不能描述成本次修订；其现有 Release 附件也是历史产物，不是修订版下载。工作树的版本号仍为 `0.59.1`，这是规范修订，不是 `0.59.2`。

## 修订后的规范范围

修订后的目录包含 **1,306 个编码形式、561 个目录助记符和八个指令分类**：

| 目录组成 | 形式数 |
| --- | ---: |
| 无作用域公共标量形式 | 473 |
| 公共命令形式 | 105 |
| Linx 专有形式 | 23 |
| 带作用域的 64 位形式 | 705 |
| **合计** | **1,306** |

23 个 Linx 专有形式包括 19 个沿用定义和 4 个仅保留编码的形式：`DMA.FREE.L`、`DMA.FREE.S`、`MCOPY.DL`、`MCOPY.DS`。这 4 个形式未实现，必须在读取操作数或产生架构效果前拒绝。

本次修订从有效指令集删除 193 个形式：184 个 `V.*` 形式及 9 个两级块入口/块体形式。PTO-SPEC 继续通过 **10 条预留记录**占有全部相关编码空间，包括一条 `V.*` 通配区域和九条具名记录。所有匹配指令均硬拒绝，不提供兼容译码器，也不得重新分配这些编码。该裁决不删除 PTO Tile VEC 引擎、`BSTART.TEPL` 载体或 `TADD` 等 Tile 操作。[架构决策](../architecture/linx-two-level-block-obsolescence.md) · 工作版目录：`isa/v0.59/linxisa-v0.59.json`

本 profile 还单独包含 119 个直接 Tile 操作、100 项系统寄存器定义和 50 条 PTO 扩展编码空间预留记录。上游依赖仍为 PTO `v0.59.1.0`，提交 `a89a53d48f5708328be609fe2e6296ac8bdb4bc2`。578 个公共形式和 705 个 scoped 形式继续由 PTO 定义。锁文件为 `isa/v0.59/pto-spec.lock.json`。

ELF 身份仍为版本 `0.59.1`、ABI `pto-isa-0.59.1-mode-function-v1` 和编码投影 SHA-256 `d90c881754d66f2cd26f6014d0b582cba88307e70123583d87fc59a918229c28`。沿用该身份不代表原始签名 tag 已包含本次修订。

## Sail 与可复现检查

v0.59.1 导出器从 1,306 形式目录生成译码器，删除旧译码与旧状态表面，强化导出树，并记录文件清单和校验和。解析、定向测试和 C 后端检查使用 Sail 0.20.2。

```sh
python3 tools/isa/select_linxisa_profile.py --profile v0.59
python3 tools/isa/build_golden.py --profile v0.59 --check
python3 tools/isa/validate_spec.py --profile v0.59
python3 tools/isa/check_pto_v0591_alignment.py
python3 tools/isa/check_v0591_candidate_dispatch_sail.py
python3 tools/isa/export_linxisa_v0591_sail.py --output /tmp/linxisa-0591-sail
python3 tools/isa/export_linxisa_v0591_sail.py --check /tmp/linxisa-0591-sail
```

修订版离线手册须从当前工作树本地生成。本地构建成功不代表附件已上传。

```sh
make -C docs/architecture/isa-manual html-reference check-html-reference
```

## 系统验证缺口

规范、目录和 Sail 相互一致，不等于芯片或整机已经通过发布资格验证。本次修订成为系统基线之前仍有以下缺口：

| 范围 | 当前证据与待完成工作 |
| --- | --- |
| 编译器与模拟器 | 早期 0.59.1 工作抽查了 71 个执行形式，并在 QEMU、linx-model、gfrun、gfsim 间核对 180 个 scoped 载体和 1,440 字节结果。这既不是全覆盖，也不是针对当前 1,306 形式修订的干净复验。LLVM active-replay lowering 仍需合法的无分支实现；编译器和 QEMU 还须证明已删除编码会被拒绝，而不会进入翻译执行。[AVS](https://github.com/LinxISA/linx-isa/pull/239) · [LLVM #182](https://github.com/LinxISA/llvm-project/pull/182) |
| LinxCore RTL | 候选修订的编码对照与流水级连接通过，但运行器和协同仿真在 pyCircuit JIT 的旧 `Wire._zext` 接口处停止。RTL 执行一致性以及十个预留范围的硬拒绝仍未完成资格验证。[LinxCore #55](https://github.com/LinxISA/LinxCore/pull/55) |
| Linux | 早期组件锁定曾通过 initramfs smoke/full boot 和诊断 BusyBox 块设备根文件系统启动。仍须使用最终编译器、模拟器、内核、rootfs 和修订规范锁定重新构建并复验。[Linux #36](https://github.com/LinxISA/linux/pull/36) |
| 整机 | 最终组件锁定、两条必需的 runtime-convergence 路径、下游旧译码的完整清除和整机资格验证仍未完成。原始 tag 与当前未打 tag 的工作修订都不具备整机通过证明。[组件锁定](https://github.com/LinxISA/linx-isa/pull/230) · [整机资格](https://github.com/LinxISA/linx-isa/pull/237) |

# LinxISA v0.58.3

LinxISA v0.58.3 将 v0.58 架构 profile 及其维护中的软件栈统一升级到已发布的
PTO ISA v0.58.3 契约。本版本是严格的兼容性边界：工具链和加载器会拒绝旧版或
混合 PTO 身份，不会静默兼容。

## 契约身份

- LinxISA profile：`v0.58`
- LinxISA release：`0.58.3`
- PTO release：`0.58.3`
- PTO 源提交：`e599a3d36ebfad43362ff591ea5e128816c684c7`
- 编码 ABI：`pto-isa-0.58.3-mode-function-v1`
- 编码投影 SHA-256：
  `8a48b80e04484c70870f155bf9efc79d2a805cf99e809f4e4e8a7e6a7eb34172`
- PTO 内容 SHA-256：
  `f299fe3d256c5d071e57bb4aaa2be2de2e4a386ae090048df1f73ae92d392678`
- 目录规模：466 条 scalar form、74 条 command form、109 条 Tile 操作和
  40 个扩展编码 reservation
- 硬件数值 profile：`pto-hardware-numeric-0.58.3-ieee-v1`

机器可读权威仍是 `isa/v0.58/release_manifest.json` 和
`isa/v0.58/pto-spec.lock.json`。所有经过审查的生态组件精确提交记录在
`docs/bringup/component-lock.v0.58.json`。

## 架构变更

- 移除 `B.EQ`、`B.NE`、`B.LT`、`B.GE`、`B.LTU`、`B.GEU`、`B.Z` 和
  `B.NZ`；原编码属于 reservation，不是兼容别名。
- 将 `B.IOT` 和 `B.IOS` 迁移到 v0.58.3 的 `SizeCode` 与 `PEMode` 字段，
  并规定 mode 0 为严格无副作用路径。
- 按精确 `SizeCode` 上限扩展 Local 与 Shared Tile 容量。
- 为 `B.FPATR` 增加 `TransA` 和 `TransB`，并更新解码掩码。
- 明确 `B.IOR.RegSrc1` 是 `TLOAD`、`TSTORE` 的字节行步长。
- 增加持久 CUBE CELL 状态、精确输入/输出 layout 传输、协作式 Shared
  transpose，以及原子的 accumulator 输出行为。
- 增加 VECTOR/CUBE 首次使用异常，用于延迟分配上下文。异常在块取得不可恢复
  资源或产生体系结构可见副作用前触发；异常返回后可重试原指令。

旧版生成页面已移至 `docs/archive/v0.58/retired-pto-0583/`，不再具有规范性。

## 生态同步

- LLVM/LLD 生成、保留、验证并链接精确的 v0.58.3 PTO 身份；MC 和 CodeGen
  实现当前 scalar、block、Tile、CUBE 与寄存器 carrier 契约。
- PTOAS 消费已合入的 LLVM 和 TileOP，并验证真实 phase-C 目标编译及精确身份
  链接。
- QEMU 实现 v0.58.3 解码与执行契约，包括首次使用异常、Tile 传输、CUBE
  layout/state 和事务化输出。
- Linx-TileOP-API 提供精确的 v0.58.3 C++ API、目标 object/link 门禁和
  fail-closed ELF 身份解析器。
- Linux、glibc 和 musl 拒绝缺失、畸形、冲突、旧版或混合 PTO 身份。维护中的
  C++ runtime 构建会针对精确 phase-C sysroot 打包 compiler-rt、libunwind、
  libc++abi 和 libc++。
- queue-wired model、PTO kernels、AVS 和智能体工作流技能 pin 到同一权威。

## 验证策略

发布只接受绑定精确 component lock 的新鲜证据。静态覆盖、仅 trace 输出、归档
报告、旧 SHA、跳过项和等待中的任务都不算通过。发布列车覆盖 ISA/Sail、
LLVM/LLD、PTOAS、QEMU、TileOP、model、Linux/libc、两个 compile-AVS 目标、
目标 C++ 链接和维护中的 PTO CUBE workload。

PTO 的 GitHub release 与 tag 已不可变，但上游 `spec/release-manifest.json`
仍保留 `specification_status: draft`。LinxISA 将其记录为元数据欠账，只对齐已发布
的 v0.58.3 tag，不吸收 v0.58.4 草案工作。

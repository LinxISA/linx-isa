# VECTOR/CUBE 首次使用异常设计

日期：2026-08-18
状态：已确认，待实现

目标：合入 LinxISA `main` 的未发布 ISA 契约。版本号、release manifest、PTO ISA 锁、PTO ELF identity 和所有发布标签保持不变。

## 1. 目标

本设计为 ACR2 用户任务增加 VECTOR/CUBE 首次使用异常，用于延迟分配、初始化、恢复和保存扩展执行上下文。同时，本设计把首次使用异常与块执行期间的内部异常明确分层，消除“CUBE 不支持可恢复异常”与“CUBE 首次使用时陷入”之间的表面矛盾。

首次使用异常是块执行前的精确同步异常。它不属于 VECTOR/CUBE 块进入执行阶段后产生的内部异常。

## 2. 已确认的编码

`E_INST (0)` 与原因码 `4` 不冲突：前者是 `TRAPNUM`，后者是 `E_INST` 原因空间中的 `CAUSE`。

本次变更只固定首次使用异常使用的 `E_INST (0)` 大类，不重编号其他已存在的异常生产者。PTO 0.58.1 已锁定的 `EBREAK` trap 50、当前 ASSERT、E_DATA、E_BLOCK 和调试异常编码全部保持不变；这些编码之间尚存的 profile 差异由独立异常分类审计处理。

首次使用异常采用以下固定编码：

| 字段 | VECTOR | CUBE |
| --- | ---: | ---: |
| `TRAPNO.E` | `1` | `1` |
| `TRAPNO.ARGV` | `1` | `1` |
| `TRAPNO.TRAPNUM` | `E_INST (0)` | `E_INST (0)` |
| `TRAPNO.CAUSE` | `EC_PERM (4)` | `EC_PERM (4)` |
| `TRAPARG0` | `0` | `1` |
| `ECSTATE.BI` | `0` | `0` |

`TRAPNO.E=1` 表示同步异常，`TRAPNO.E=0` 表示异步中断。该定义与当前 Linux 和 QEMU 的有效线级契约一致。

本机制中 `EC_PERM` 的线级值就是 `CAUSE=4`，不是 `0x0400`。该规定只约束首次使用异常的完整信封，不顺带改写其他 E_INST 生产者已经采用的 profile-specific CAUSE 格式。

归档 v0.55 文档中的 `E_PEREM` 是 `EC_PERM` 的历史拼写错误。活动规范、机器可读状态和实现不得新增 `E_PEREM` 同义编码；归档文件保持原样。

## 3. 现有契约校正

当前仓库存在以下与本机制直接相关的投影漂移，实施时必须修正：

- `docs/isa/register/ssr/TRAPNO.md`、`docs/zh/isa/register/ssr/TRAPNO.md` 和 Linux 将 `E_INST` 定义为 `TRAPNUM=0`；QEMU 也使用 `LINX_TRAPNUM_INSN_EXP=0`。
- `TRAPNO.E` 在部分生成状态中被反向描述为异步标志，但活动寄存器文档、Linux 和 QEMU 均把 `E=1` 用于同步异常。

实施后，机器可读权威必须为首次使用异常提供独立且精确的 `{E, ARGV, TRAPNUM, CAUSE, TRAPARG0, BI}` 定义。现有 `bringup_trapnums`、PTO EBREAK、ASSERT、E_DATA、E_BLOCK 和调试异常表不在本次重编号范围内。

## 4. 触发范围

### 4.1 VECTOR

VECTOR 首次使用异常覆盖以下活动块头及其压缩形式：

- `BSTART.MPAR`
- `BSTART.MSEQ`
- `BSTART.VPAR`
- `BSTART.VSEQ`
- 对应的 `C.BSTART.*` 形式

本版本不把 TEPL 载体上的 `BSTART.VEC`/`BSTART.SFU` 自动归入该首次使用异常。它们的上下文所有权仍由 Tile 执行上下文定义管理。若后续版本决定它们与 VECTOR 上下文共享保存单元，必须通过新的显式架构变更扩展触发集合。

### 4.2 CUBE

CUBE 首次使用异常覆盖机器可读操作状态中 `family=CUBE` 的块头操作及其合法汇编别名。判断依据来自 v0.58 机器权威，不允许实现维护一份独立的手写名称表。

### 4.3 ACR 范围

当前 v0.58 profile 只规定 ACR1 内核管理 ACR2 用户任务的行为：

- ACR2 即将执行 VECTOR 块头时读取 `ECONFIG_ACR1.V`。
- ACR2 即将执行 CUBE 块头时读取 `ECONFIG_ACR1.C`。
- ACR0/ACR1 自身执行相同块头时不触发本机制。

其他 ACR 层级的嵌套管理留给后续 profile，不由本次变更推断。

## 5. 精确触发边界和优先级

首次使用检查位于合法块头进入执行前的接受边界，处理顺序为：

1. 完成取指、长度识别和基本编码合法性检查；
2. 完成当前 ACR 的执行权限检查；
3. 确定块类型是本机制覆盖的 VECTOR 或 CUBE；
4. 检查 `ECONFIG_ACR1.V/C`；
5. 若相应位为 `1`，产生首次使用异常；
6. 仅在未产生异常时，分配块上下文、写入块描述符、占用执行队列或发出执行请求。

因此：

- 非法编码、非法参数或权限失败优先于首次使用异常；
- 首次使用异常发生前不得写入块寄存器、修改 BARG/BSTATE、发出访存请求或占用不可回滚资源；
- `EBARG_BPC_CUR`、异常返回 PC 和诊断 PC 均指向原始触发块头；
- `ECSTATE.BI=0`，因为块体尚未开始；
- 处理程序返回后可直接重新执行原始块头，不会重复任何体系结构副作用。

首次使用异常的完整识别签名是 `E=1, ARGV=1, TRAPNUM=E_INST, CAUSE=EC_PERM` 且 `TRAPARG0` 为定义的扩展类型值。普通权限异常不得伪造该完整签名。

## 6. ECONFIG 扩展

`ECONFIG_ACRn` 保持 64 位、每硬件线程和每管理 ACR 独立。当前未发布主线契约固定位定义为：

| 位 | 名称 | 语义 |
| ---: | --- | --- |
| `0` | `E` | 外部中断使能 |
| `1` | `T` | 定时器中断使能 |
| `2` | `S` | 软件中断使能 |
| `3` | `A` | `ASSERT` 指令异常使能 |
| `31:4` | Reserved | 写入必须为零，读出为零 |
| `32` | `V` | VECTOR 首次使用异常使能 |
| `33` | `C` | CUBE 首次使用异常使能 |
| `63:34` | Reserved | 写入必须为零，读出为零 |

复位值为 `0x0000000300000008`：`A/V/C=1`，中断使能位和保留位为零。软件在开放 ACR2 用户执行之前必须写入当前任务所需的最终值，不能只依赖硬件复位值。

写 `V=0` 只关闭 VECTOR 首次使用异常；写 `C=0` 只关闭 CUBE 首次使用异常。处理其中一种首次使用异常不得隐式清除另一种使能位。

## 7. 软件状态模型

体系结构不强制 Linux 内部字段名，但要求软件能分别表示每类扩展的以下状态：

| 状态 | 已分配上下文 | 硬件中已恢复 | 对应 `ECONFIG` 位 |
| --- | --- | --- | --- |
| `NEVER_USED` | 否 | 否 | `1` |
| `SAVED_NOT_RESTORED` | 是 | 否 | `1` |
| `LIVE` | 是 | 是 | `0` |

Linux profile 可以用 `TIF_VECTOR`/`TIF_CUBE` 表示“已经使用过”，并增加独立的 resident/loaded 状态区分 `SAVED_NOT_RESTORED` 与 `LIVE`。单一 `TIF_*` 位不足以实现延迟恢复。

### 7.1 首次分配

首次使用处理程序看到 `NEVER_USED` 时：

1. 分配对应上下文保存空间；
2. 按体系结构复位值初始化上下文；
3. 标记该扩展已使用且已装入硬件；
4. 只清除对应的 `V` 或 `C` 位；
5. 返回 ACR2 并重试原始块头。

### 7.2 延迟恢复

处理程序看到 `SAVED_NOT_RESTORED` 时：

1. 不重新分配上下文；
2. 恢复已有上下文；
3. 标记上下文已装入硬件；
4. 只清除对应的 `V` 或 `C` 位；
5. 返回并重试原始块头。

### 7.3 调度切换

换出任务时，仅保存已经使用且当前驻留在硬件中的扩展上下文。切入任务时：

- 立即恢复策略：恢复上下文并清除对应 `V/C` 位；
- 延迟恢复策略：保持保存态并设置对应 `V/C` 位；
- 从未使用：不分配、不恢复并设置对应 `V/C` 位。

## 8. 块执行期间的异常

首次使用异常与块执行内部异常遵循不同规则：

1. VECTOR 块可以产生体系结构定义的可恢复内部异常。硬件必须冻结异常块并保留恢复所需状态。
2. CUBE 块执行期间不产生 CUBE 自有的可恢复内部异常。非法块头仍可在执行前产生 `E_INST/E_BLOCK`；不可恢复硬件错误按机器检查或终止策略处理。
3. TLSU（原 TMA）不产生 TLSU 自有的可恢复内部异常。地址翻译、访问权限和总线访问错误属于访存系统产生的 `E_DATA`，不是 TLSU 私有异常。
4. VECTOR/CUBE 首次使用异常发生在块执行前，不受上述内部异常能力限制。

活动规范统一使用 `TLSU`。`TMA` 只可出现在明确标记为历史兼容或归档的文本中。

## 9. 异常块状态与上下文状态

规范区分两类保存对象：

- **扩展上下文状态**：任务长期拥有的 VECTOR/CUBE 寄存器和扩展控制状态，供任务切换保存与恢复。
- **异常块内部状态**：恢复一个已开始执行的块所需的进度、序列控制、谓词、依赖、完成队列、未决访存和实现定义游标。

对于可恢复 VECTOR 内部异常，仅保存寄存器内容不构成完整恢复证据。实现必须保存该块继续执行所需的全部架构状态；微架构可以保存更多状态，但不得要求软件理解未公开的内部编码。

## 10. ESAVE 前向进展

异常块冻结后不得阻断状态保存路径。实现必须满足以下任一条件：

- 为 `ESAVE` 提供独立执行通路；
- 为 `ESAVE` 预留不可被普通块占用的寄存器、队列项和发射槽；
- 提供等价的硬件保存入口，保证在普通相关资源满载时仍可完成状态导出。

验证必须覆盖“异常块占满普通可用资源后，ESAVE 仍能发射并完成”的最坏情况。依赖软件重试但无法证明资源最终释放，不满足前向进展要求。

## 11. 机器权威和文档投影

实现阶段只维护一份机器可读源，并由其驱动文档与模型检查。至少包括：

- `isa/v0.58/state/system_registers.json`：首次使用异常信封、`TRAPNO.E/ARGV`、`ECONFIG` 位和复位值；
- `isa/v0.58/semantics_conventions.json`：首次使用触发边界、精确性、优先级和状态保持规则；
- `docs/architecture/isa-manual/src/chapters/10_system_and_privilege.adoc`：英文规范投影；
- `docs/isa/exception/exception.md`、`docs/zh/isa/exception/exception.md`：双语异常章节；
- `docs/isa/register/ssr/ECONFIG.md`、`docs/zh/isa/register/ssr/ECONFIG.md`：双语寄存器章节。

生成的 `linxisa-v0.58.json`、Sail 状态和手册表必须与上述权威逐字段一致。

## 12. 下游实现边界

架构变更合入后，下游按以下顺序实现：

1. Sail：实现首次使用 `E_INST(0)/EC_PERM(4)`、ECONFIG 位、执行前检查和无副作用重试，不改写其他异常编号。
2. QEMU：在块头接受边界实现 VECTOR/CUBE 检查，并添加精确陷入与重试测试。
3. Linux：实现任务状态机、首次分配、延迟恢复、独立 V/C 位管理和切换保存。
4. LinxCore/模型：在资源分配前产生异常，证明重命名、队列和块状态零副作用，并证明 ESAVE 前向进展。

下游不得在架构机器契约明确之前独立选择位号、原因码、触发集合或优先级。

## 13. 验证要求

必须新增以下回归：

- 机器契约精确检查：`E_INST=0`、`EC_PERM=4`、`V=32`、`C=33`、复位值和保留位行为；
- VECTOR/CUBE 正例：使能时产生 `E_INST(EC_PERM)`，`TRAPARG0` 分别为 `0/1`；
- 选择性清除：处理 VECTOR 后 CUBE 仍能首次陷入，反之亦然；
- 禁用正例：对应位为零时不产生首次使用异常；
- 精确性：异常前块寄存器、BARG/BSTATE、执行队列、访存和完成状态均不变化；
- 重试：处理程序清位/恢复后，同一 PC 的原始块头只执行一次；
- 优先级：非法编码和权限错误不会被首次使用异常遮蔽；
- 上下文切换：`NEVER_USED`、`SAVED_NOT_RESTORED`、`LIVE` 三态覆盖；
- VECTOR 内部可恢复异常状态完整性；
- CUBE/TLSU 私有内部异常禁用与 TLSU `E_DATA` 访存错误区分；
- ESAVE 资源满载时的前向进展；
- 英文、中文和生成手册中的编码与术语一致。

## 14. 不采用的方案

### 14.1 仅修改中文文档

该方案会保留机器状态、Sail、英文手册和下游实现之间的冲突，不能形成可执行规范。

### 14.2 新增独立 TRAPNUM

首次使用异常已经有 `E_INST(0)/EC_PERM(4)` 编码。新增大类会破坏现有 Linux/QEMU ABI，并增加不必要的路由和保存规则。

### 14.3 同时清除 V/C

该方案会使只使用过一种扩展的任务绕过另一种扩展的首次使用异常，无法保证按需分配。

## 15. 完成标准

设计实现完成需要同时满足：

- 活动机器权威包含唯一的首次使用异常信封和一致的 `TRAPNO.E` 位语义；
- 首次使用异常编码、位号、触发集合和精确边界均有机器可读定义；
- 中英文规范和生成手册完全同步；
- Sail 及所有新增静态回归通过；
- QEMU、Linux 和 LinxCore 的明确下游要求已经记录，且实现不得使用不同编码；
- 现有非首次使用异常编号保持不变，其他分类漂移已记录为独立审计范围；
- v0.58 mandatory ISA/documentation gates全部通过。

本设计不执行 release 操作：不得修改 `isa/v0.58/meta.json`、`release_manifest.json`、PTO lock、release 导航或任何标签。后续发布版本由其他功能修复和消费者实现完成后统一决定。

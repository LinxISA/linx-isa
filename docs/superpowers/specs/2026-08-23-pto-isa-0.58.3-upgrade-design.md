# LinxISA / PTO ISA 0.58.3 upgrade design

## Objective

Move the LinxISA v0.58 superproject from PTO ISA 0.58.1 to the published PTO
ISA 0.58.3 release, update every ABI-dependent consumer, prove the rebuilt
stack end to end, and publish a matching immutable LinxISA release.

The upstream authority is PTO-SPEC tag `v0.58.3`, commit
`e599a3d36ebfad43362ff591ea5e128816c684c7`, tree
`abb6899d2e664e378ac9c1b77062670daa4d31b4`.

0.58.1 artifacts must fail closed.

## Architectural hard breaks

1. `B.EQ`, `B.NE`, `B.LT`, `B.GE`, `B.LTU`, `B.GEU`, `B.Z`, and `B.NZ`
   leave the common instruction set. Their former words become extension
   reservations and do not silently become Linx-owned instructions.
2. `B.IOT` and `B.IOS` encode `SizeCode` in bits 18:15 and `PEMode` in bits
   11:9. The old `PE_MASK`/`TSize` words do not retain their meaning.
3. The fixed `PEMode` decoder produces masks `0000`, `1000`, `0100`, `0010`,
   `0001`, `1100`, `1110`, and `1111`. Mode zero is a strict no-effect path.
4. Local destination SizeCode 1..10 represents 128 B..64 KiB per
   participating PE. Shared destination SizeCode 1..12 represents
   128 B..256 KiB.
5. `B.FPATR` adds `TransA` and `TransB`, and its decode mask changes.
6. `B.IOR.RegSrc1` is a byte row stride for TLOAD/TSTORE.
7. CUBE gains persistent CELL state, GM/local layout transport, local matrix
   operands, cooperative Shared transpose, and atomic accumulator-output
   contracts.

## Repository order

1. Publish a draft LinxISA authority PR containing the exact PTO lock,
   generated catalogs/codecs/Sail model, English and Chinese pages, and
   hard-break tests.
2. Update LLVM/LLD against that immutable reviewed authority commit. Merge the
   leaf PR only after MC, LLD, CodeGen, linx32/linx64 AVS, and TileOP compile
   gates pass.
3. Rebase QEMU 0.58.3 work onto current `master` so first-use behavior and
   executable/VMState tests remain present. Merge after native, Python,
   executable, strict AVS, and full AVS gates.
4. Update Linx-TileOP-API from canonical `linx`, regenerate its provenance,
   and run `make check`, full compile/disassembly, and negative tests with the
   merged compiler.
5. Repin merged leaf SHAs and component-lock rows atomically in the LinxISA
   PR. Update Linux/libc/model/RTL consumers when exact-identity or generated
   catalog gates require it.
6. Run release-strict cross-model, QEMU/Linux, libc, TileOP, PTO-kernels, and
   workload gates using one exact component manifest.
7. Require hosted checks on the reviewed root head, merge it, prove tree
   equality, publish annotated tag/release `v0.58.3`, and delete only merged
   topic branches.

## Release gates

- canonical ISA/golden/manifest/codecs/documentation
- Sail parser, directed semantics, coverage, and C backend
- LLVM MC/LLD/CodeGen and both compile AVS targets
- QEMU source/native/executable/strict/full AVS
- TileOP `make check`, compile-all, disassembly, and negatives
- component lock and repository layout
- QEMU, model, LinxCore/pyCircuit, Linux, musl, and glibc exact-identity lanes
- release-strict result-memory comparison and end-to-end workload smoke

Pending, skipped, stale-SHA, trace-only, or archived evidence is not a pass.

## Runtime closure record

The maintained CUBE corpus passes six independent full-system boots on exact
LLVM `b7c83f68`, QEMU `2ba240fd`, Linux `1055a743`, TileOP `bd1ecca9`, and
pto-kernels `5f5cf061`. The fail-closed aggregate validates actual source/tool,
kernel, QEMU binary, PTO lock, libc, loader, and identity-parser hashes and is
recorded by SHA-256
`3328caf983ae9f555b926b818d89795fb8e13650bd13a9ce0c925a6b8a29761a`.

The sequential six-process diagnostic exposes the expected absence of
cross-process Tile context management while Linux keeps `ECONFIG.V/C`
disabled. It remains tracked by LinxISA issue 182 and Linux issue 32 and is not
misrepresented as cold-boot program failure.

## Governance note

The GitHub release is published and its exact-SHA release workflow passed, but
the upstream manifest still records `specification_status: draft`. This is
recorded as an upstream metadata caveat; downstream alignment uses the
immutable published tag and does not absorb PTO work targeted at 0.58.4.

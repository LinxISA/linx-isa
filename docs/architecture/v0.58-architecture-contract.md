# LinxISA v0.58 Architecture Contract

This branch carries the review-only PTO ISA 0.58.7 hard-break integration. Its machine-readable
authority is `isa/v0.58/linxisa-v0.58.json` together with the state and release
artifacts under `isa/v0.58/`.

## PTO alignment

The imported PTO ISA 0.58.7.0 publication baseline contains:

- 466 scalar forms;
- 96 command forms (92 CMD and 4 BBD);
- 118 tile operations encoded in 78 TEPL, 28 TLSU, and 12 CUBE families.

The architectural execution engines are exactly:

- 31 VEC operations for element-wise Tile/Tile and Tile/scalar computation;
- 47 SFU operations for complex Tile computation;
- 28 TLSU operations for memory, indexed GM atomic/reduction, and Tile data
  movement; and
- 12 CUBE operations for matrix and matrix-vector computation.

TEPL is the unchanged Mode/Function encoding carrier for the VEC and SFU
operations; it is not an execution engine. `BSTART.TEPL` remains the unique
compiled decode identity. Assemblers also accept `BSTART.VEC` and
`BSTART.SFU`, and canonical disassembly selects the alias that matches the
operation's catalogued engine.

The seven normative operation classes are 26 element-wise Tile/Tile,
15 Tile/scalar-and-immediate, 28 reduce-and-expand, 27
memory-and-data-movement, 12 matrix-and-matrix-vector, 6
layout-and-rearrangement, and 4 irregular-and-complex operations.

The TLSU surface retains the base, mask, and compare-and-swap indexed forms and
adds the reviewed GM exchange, min/max, add, increment/decrement, bitwise, and
population-count variants. `BSTART.TIMG2COL` owns feature-map IMG2COL at TLSU
Function 28; the former direct `TIMG2COL` Tile operation remains retired.

`TCONCAT`, `TEXTRACT`, `TINSERT`, `THISTOGRAM`, `TQUANT`, `TDEQUANT`,
`TSORT`, and `TMRGSORT` are retired without compatibility aliases. Their old
complete encodings must reject before operand reads or architectural effects.

`isa/v0.58/pto-spec.lock.json` pins the reviewed PTO source commit, tree,
catalog hashes, release hash, encoding projection, and numeric profile.

The effective Linx scalar source is intentionally distinct from that immutable
publication baseline. `isa/v0.58/state/pto_scalar_forms.json` preserves all 466
published scalar forms, while `isa/v0.58/state/pto_scalar_proposal.json` records
the proposed replacement encodings for 44 existing forms plus six new atomic
forms and the already accepted PTO `SYNC.CORE` form. The effective scalar
inventory contains 473 forms and is compared in full with the companion PTO PR. The build applies
that proposal through `tools/isa/pto_scalar_proposal.py`; it does not rewrite or
misidentify the locked PTO publication.

## Linx-only extensions

Linx retains 212 additive two-level forms: 184 `V.*` forms plus 28 command
forms, including the four vector block headers. PTO ISA 0.58.7 publishes 46
extension reservations that cover every retained form and the nonzero Fixup
displacement spaces. Apart from the four encoding-only resource reservations defined
below (checked against the companion PTO proposal in
`tools/isa/check_pto_scalar_proposal.py`),
Linx MUST NOT retain a form outside those reservations.

## Linx-only store-op scalar extension (v0.58 amendment)

Beyond the published PTO baseline, the active Linx review candidate imports
the six new scalar forms from the companion PTO proposal and retains four
encoding-only resource reservations:

- `SW.SUB` and `SD.SUB` use op5 `0_1000` (b31=0, SUB opcode `1000` at
  b30..27);
- `SB.ADD`, `SB.SUB`, `SH.ADD`, and `SH.SUB` reuse the SW/SD slots with the
  op5 size-override bit b31 set (`1_0000` and `1_1000`; the SW slot shrinks
  to byte, the SD slot to halfword);
- `DMA.FREE.S`, `DMA.FREE.L`, `MCOPY.DS`, and `MCOPY.DL` retain only
  their encodings and operand fields. They are **not implemented**. Execution
  rejects before operand reads or architectural effects; no copy, allocation,
  release, result address, or completion semantics are provided.

The atomic main class (`6..4=000`) now reads its top five bits `31..27` as a
unified op5 field: **b30..27 carries the operation/size code** (b27, formerly
the far flag, is absorbed as the code's least-significant bit, keeping the
sequential numbering ADD=0000 … UMIN=0111, SUB=1000) and **b31 is the flag
bit** — the size override for the store-op forms and the relocated far flag
for LR/SC/SWAP and the load-op forms. The `.f` suffix is removed from the
store-op forms. Because the model never implemented far, the forty-four
affected existing atomic forms (LR/SC/LW/LD/SW/SD/SWAP) are re-encoded with
the code shifted one bit down. The explicit 44-form proposal records the
amended masks, matches, and the far field's new bit position, while the locked
0.58.7.0 catalog remains unchanged. `check_pto_v058_manifest.py` freezes the
exact four-form reservation set. These proposal records state the intended ISA
contract; they do not by themselves claim compiler, emulator, RTL, or model
implementation completion.

## Shared tile registers

Each core owns one bank of 64 Shared tile registers named `S0` through
`S63`. The names are absolute indices. The four PEs in the core may access
every register in that bank; another core has a different bank.

`B.IOS Sx, mask=<PE_MASK>` binds a source and
`B.IOS mask=<PE_MASK>, ->Sx<SizeCode>` binds a destination. The assembler maps
the eight accepted semantic masks to the encoded `PEMode`. Shared writes
atomically update descriptor and payload state. Reads do not update the
descriptor. Uninitialized reads behave like reads of undefined registers.

`B.ASSEMBLE` names its four-bit writer extent field `WriterSizeCode`.
Participating writers use nonzero Local codes 1 through 10 or Shared codes 1
through 12; code zero is reserved for discarded groups, and codes 13 through
15 are illegal.

The common three-bit `PEMode` decoder maps codes `0..7` to masks `0000`,
`1000`, `0100`, `0010`, `0001`, `1100`, `1110`, and `1111`. Mode zero is a
strict no-effect path. `B.IOT` is Local-only. The
architecture specifies no inter-PE order beyond atomic read-modify-write;
software must prevent conflicting accesses.

Local `SizeCode` values 1 through 10 denote 128 B through 64 KiB per
participating PE. Shared destination values 1 through 12 denote 128 B through
256 KiB for the complete Core-wide Shared object. Descriptor rows and columns are powers of
two, rows are derived from SizeCode, columns, and element size, and valid
rows/columns may not exceed the allocated shape. Matrix operations obey the
same shape constraints.

For TLOAD/TSTORE, `B.IOR.RegSrc0` selects the GM base and
`B.IOR.RegSrc1` selects row stride in bytes. Every selected PE
resolves those selectors in its private GPR file. Omitting B.IOR selects base
zero and dense row bytes; an explicitly encoded zero stride remains zero.
The element address is
`base + row * row_stride_bytes + column * element_size`; packed four-bit data uses
the logical element index to select its containing byte and nibble.

For indexed TLSU gather/scatter operations, explicit `B.IOR.RegSrc0` supplies
the GM base. `RegSrc1`, `RegSrc2`, and `RegDst` encode zero; there is no scalar
row-stride operand. Each S32, U32, S64, or U64 index-Tile entry is a byte
displacement used without scaling or row/column decomposition, so the address
is `base + sign_or_zero_extended_byte_displacement`. This rule does not change
the repeated `B.IOR` stream used only by Linx vector bodies.

## Version boundary

This review candidate is a hard break from v0.57. Old command encodings and retired
tile selectors are illegal. Toolchains must consume the v0.58 generated
catalog and codecs; no old decode is part of the v0.58 architecture.

## Implementation references

LinxCore implementation contracts are published under
`docs/architecture/linxcore/`. They may retain their own implementation
baseline labels, but they do not override this v0.58 ISA contract.

## Proposal integration status

The active scalar proposal is binary-incompatible with the published PTO
0.58.7.0 atomic encodings. The publication lock records the immutable baseline;
it is not a claim that proposal binaries carry a compatible published ELF
identity. Publication and downstream promotion must wait for an accepted PTO
identity and aligned compiler/emulator pins. `SYNC.CORE` is also decode-only in
the single-context Sail subset; PTO owns its four-PE rendezvous semantics.

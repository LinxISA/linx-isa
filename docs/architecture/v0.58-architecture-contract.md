# LinxISA v0.58 Architecture Contract

PTO-SPEC is the sole golden source for the common scalar, command, and Tile
architecture. The catalog development commit and all catalog hashes are pinned
in `isa/v0.58/pto-scalar-proposal.lock.json`. The compiled Linx design is
`isa/v0.58/linxisa-v0.58.json`; `tools/isa/import_pto_golden.py` regenerates its
common inputs directly from that PTO revision. Linx does not maintain a
separate scalar amendment table. The scoped runtime-startup semantic binding
below has its own exact source lock.

## Current golden inventory

- 473 scalar forms and 105 command forms;
- 119 Tile operations: 79 TEPL, 28 TLSU, and 12 CUBE encodings;
- four semantic engines: 32 VEC, 47 SFU, 28 TLSU, and 12 CUBE operations;
- 50 occupied encoding reservations, including four unimplemented resource forms.

TEPL is the unchanged Mode/Function encoding carrier for VEC and SFU, not an
execution engine. BSTART.TEPL is the compiled carrier; BSTART.VEC and BSTART.SFU
remain assembly aliases selected by the operation's golden engine annotation.
The current golden includes TEXPDIF and TLEA. Retired names and unassigned
selectors follow the golden catalogs without downstream aliases.

The seven operation classifications are 26 element-wise Tile/Tile,
16 Tile/scalar-and-immediate, 28 reduce-and-expand, 27 memory-and-data-movement,
12 matrix-and-matrix-vector, 6 layout-and-rearrangement, and 4 irregular-and-complex.

## Scalar atomic contract

The golden owns the re-encoded 44 atomic forms and six new store-only forms:
SW.SUB, SD.SUB, SB.ADD, SB.SUB, SH.ADD, and SH.SUB. Bits 30..27 carry the
operation/size code; bit 31 carries far for LR/SC/SWAP/load-return forms or
size override for store-only forms. Store-only forms have no far suffix.
Subtraction wraps at the selected access width and does not publish the old value.

DMA.FREE.S/L and MCOPY.DS/DL retain only encoding and operand fields. They are
**NOT IMPLEMENTED** and reject execution before operand reads or architectural
effects. No copy, replica address, allocation, release, or completion behavior
is provided by these reservations.

Every block-local dimension register `LB0`, `LB1`, and `LB2` has effective
value 1 when the block omits its `B.DIM` or `C.B.DIMI` write. An explicit
write, including zero, replaces that default. Dimension-presence bookkeeping
exists only for duplicate-write rejection and trap recovery; operation
legality and execution must not distinguish omission from explicit value 1 or
derive an omitted dimension from a Tile descriptor. Toolchains therefore omit
resolved value-1 dimension commands.

## Linx-only extensions

Linx retains 184 V.* forms and 28 two-level command forms inside the exact PTO
reserved spaces. Their semantics remain Linx-specific. The common golden
comparison also verifies all four resource reservations.

## Shared tile registers

Each core owns one bank of 64 Shared tile registers named `S0` through
`S63`. The names are absolute indices. The four PEs in the core may access
every register in that bank; another core has a different bank.

`B.IOS Sx, mask=<PE_MASK>` binds a source and
`B.IOS mask=<PE_MASK>, ->Sx<SizeCode>` binds a destination. The assembler maps
the eight accepted semantic masks to the encoded `PEMode`. Shared writes
atomically update descriptor and payload state. Reads do not update the
descriptor. Uninitialized reads behave like reads of undefined registers.

`B.ASSEMBLE` names its four-bit writer extent field `WriterSizeCode`.
Participating writers use nonzero Local codes 1 through 10 or Shared codes 1
through 12; code zero is reserved for discarded groups, and codes 13 through
15 are illegal.

The common three-bit `PEMode` decoder maps codes `0..7` to masks `0000`,
`1000`, `0100`, `0010`, `0001`, `1100`, `1110`, and `1111`. Mode zero is a
strict no-effect path. `B.IOT` is Local-only. The golden also defines explicit LAST and LL/LR/RL
binding forms; their exact operand and fixed-bit constraints come from the
command catalog. The
ordinary accesses provide no implicit inter-PE synchronization. Explicit
SYNC.CORE supplies its defined collective ordering; software must prevent
unsynchronized conflicting accesses.

Local `SizeCode` values 1 through 10 denote 128 B through 64 KiB per
participating PE. Shared destination values 1 through 12 denote 128 B through
256 KiB for the complete Core-wide Shared object. Descriptor rows and columns are powers of
two, rows are derived from SizeCode, columns, and element size, and valid
rows/columns may not exceed the allocated shape. Matrix operations obey the
same shape constraints.

For TLOAD/TSTORE, `B.IOR.RegSrc0` selects the GM base and
`B.IOR.RegSrc1` selects row stride in bytes. Every selected PE
resolves those selectors in its private GPR file. Omitting B.IOR selects base
zero and dense row bytes; an explicitly encoded zero stride remains zero.
The element address is
`base + row * row_stride_bytes + column * element_size`; packed four-bit data uses
the logical element index to select its containing byte and nibble.

For indexed TLSU gather/scatter operations, explicit `B.IOR.RegSrc0` supplies
the GM base. `RegSrc1`, `RegSrc2`, and `RegDst` encode zero; there is no scalar
row-stride operand. Each S32, U32, S64, or U64 index-Tile entry is a byte
displacement used without scaling or row/column decomposition, so the address
is `base + sign_or_zero_extended_byte_displacement`. This rule does not change
the repeated `B.IOR` stream used only by Linx vector bodies.

## Version boundary

This review candidate is a hard break from v0.57. Old command encodings and retired
tile selectors are illegal. Toolchains must consume the v0.58 generated
catalog and codecs; no old decode is part of the v0.58 architecture.

## Implementation references

LinxCore implementation contracts are published under
`docs/architecture/linxcore/`. They may retain their own implementation
baseline labels, but they do not override this v0.58 ISA contract.


## Executable subset

Specification presence, decode support, and execution support are separate.
The Sail model rejects new LAST/LL/LR/RL forms and nonzero ExecutionMask
controls before effects until their semantics are implemented. SYNC.CORE is
also decode-only in this single-context model. All such limits are explicit in
`isa/sail/semantics_policy.json`; the PTO definitions themselves are unchanged.

## Four-PE runtime startup ABI

The scoped software ABI binding is `isa/v0.58/pto-runtime-startup.lock.json`;
`state.pto_runtime_startup` in the compiled catalog projects the six exact PTO
NDF clauses from commit `2209562859a89be80b73ea926f5d60b9d018faae`.
This binding adopts the startup decision merged by PTO PR #415, alongside the
existing scalar/catalog lock. It does not replace that lock or assign a new
encoding/publication identity. Regenerate and verify the binding with
`tools/isa/pto_runtime_startup.py` using the frozen upstream Git objects.

The inherited startup protocol gives the four independent PE contexts a common
entry and PE0 the shared-initialization role. Workers perform private bootstrap
and meet PE0 at the same generation-zero `SYNC.CORE`; work starts after release.
The imported clauses own the exact sequencing, GM ordering, recovery, failure
and relaunch rules. Process construction and per-invocation preparation have
distinct lifetimes. A barrier cannot create the PE contexts it waits for.

The canonical read-only `THREAD_ID` entry is SSR `0x0026`, with executing PE
identity `0..3`; it is distinct from an OS thread ID, Core ID, vector lane and
Linx group/lane counters. Legal access uses the inherited SYS-block SSRGET or
HL.SSRGET contract. This binding does not assign legacy address `0x0802`.

### Downstream adaptation requirements

| Component | Required update and evidence |
| --- | --- |
| LLVM/compiler-rt and linker | Common startup entry, legal identity/barrier lowering, single shared initializer and preserved memory-order boundary; provide disassembly and exact revisions. |
| musl/glibc and runtime | Independent live stacks/private bootstrap; PE0-owned shared/process initialization; declared TLS/service permissions; repeated launch and fatal initialization tests. |
| Linux/platform/firmware loader | Real four-PE contexts, entry/argument/stack bindings, invocation identity, completion/fault/abort/reset transport. SMP or pthread creation alone is insufficient. |
| QEMU, ASL-Model, LinxCoreModel and RTL | Independent contexts, real arrivals and waiting, no synthetic release; verify both arrival orders, missing participants, failure and same-entry relaunch isolation. |
| TileOP and workloads | Route four-PE launches through this startup ABI, keep single-context guards, compare the same ELF and bindings across models with independent golden output. |

Each component records an implementation PR, merged revision and the runtime-only
common-entry ELF results before claiming support. The same ELF must demonstrate
four IDs, stack isolation, one shared initializer and initialized-data visibility.
No component pins are advanced by this specification-only update.

The current Sail model remains single-context: `SYNC.CORE` is decode-only and
`THREAD_ID` is not yet executable. Importing a contract is not evidence that
four-PE launch or runtime execution is implemented. Concrete ELF identifiers,
parameter/stack/TLS layout, launch transport and complete fd/syscall/exit policy
remain tracked by [PTO #150](https://github.com/PTO-ISA/pto-spec/issues/150) and
[PTO #386](https://github.com/PTO-ISA/pto-spec/issues/386).

# LinxISA v0.58 Architecture Contract

This branch carries the review-only PTO ISA 0.58.5 hard-break integration. Its machine-readable
authority is `isa/v0.58/linxisa-v0.58.json` together with the state and release
artifacts under `isa/v0.58/`.

## PTO alignment

The scalar, block, and tile surfaces match PTO ISA 0.58 exactly:

- 466 scalar forms;
- 76 command forms (71 CMD and 5 BBD);
- 108 tile operations encoded in 86 TEPL, 10 TLSU, and 12 CUBE families.

The architectural execution engines are exactly:

- 31 VEC operations for element-wise Tile/Tile and Tile/scalar computation;
- 55 SFU operations for complex functions, reductions/expands, rearrangement,
  and irregular operations;
- 10 TLSU operations for memory and Tile data movement; and
- 12 CUBE operations for matrix and matrix-vector computation.

TEPL is the unchanged Mode/Function encoding carrier for the VEC and SFU
operations; it is not an execution engine. `BSTART.TEPL` remains the unique
compiled decode identity. Assemblers also accept `BSTART.VEC` and
`BSTART.SFU`, and canonical disassembly selects the alias that matches the
operation's catalogued engine.

The seven normative operation classes are 25 element-wise Tile/Tile,
15 Tile/scalar-and-immediate, 28 reduce-and-expand, 9 memory-and-data-movement,
12 matrix-and-matrix-vector, 10 layout-and-rearrangement, and 9
irregular-and-complex operations.

The TLSU surface retains `BSTART.MGATHER.MASK`,
`BSTART.MSCATTER.MASK`, and `BSTART.MGATHER.CAS`, with direct tile operations
`MGATHER_MASK`, `MSCATTER_MASK`, and `MGATHER_CAS`.

`isa/v0.58/pto-spec.lock.json` pins the reviewed PTO source commit, tree,
catalog hashes, release hash, encoding projection, and numeric profile.

## Linx-only extensions

Linx retains 212 additive two-level forms: 184 `V.*` forms plus 28 command
forms, including the four vector block headers. PTO ISA 0.58.5 publishes 46
extension reservations that cover every retained form and the nonzero Fixup
displacement spaces. Linx MUST NOT retain a form outside those reservations.

## Shared tile registers

Each core owns one bank of 64 Shared tile registers named `S0` through
`S63`. The names are absolute indices. The four PEs in the core may access
every register in that bank; another core has a different bank.

`B.IOS Sx, mask=<PE_MASK>` binds a source and
`B.IOS mask=<PE_MASK>, ->Sx<SizeCode>` binds a destination. The assembler maps
the eight accepted semantic masks to the encoded `PEMode`. Shared writes
atomically update descriptor and payload state. Reads do not update the
descriptor. Uninitialized reads behave like reads of undefined registers.

The common three-bit `PEMode` decoder maps codes `0..7` to masks `0000`,
`1000`, `0100`, `0010`, `0001`, `1100`, `1110`, and `1111`. Mode zero is a
strict no-effect path. `B.IOT` is Local-only. The
architecture specifies no inter-PE order beyond atomic read-modify-write;
software must prevent conflicting accesses.

Local `SizeCode` values 1 through 10 denote 128 B through 64 KiB per
participating PE. Shared destination values 1 through 12 extend the same
power-of-two map through 256 KiB. Descriptor rows and columns are powers of
two, rows are derived from SizeCode, columns, and element size, and valid
rows/columns may not exceed the allocated shape. Matrix operations obey the
same shape constraints.

For TLOAD/TSTORE, `B.IOR.RegSrc0` selects the GM base and
`B.IOR.RegSrc1` selects row stride in bytes. Every selected PE
resolves those selectors in its private GPR file. Omitting B.IOR selects base
zero and dense row bytes; an explicitly encoded zero stride remains zero.
The element address is
`base + row * row_stride_bytes + column * element_size`; packed four-bit data uses
the logical element index to select its containing byte and nibble.

## Version boundary

This review candidate is a hard break from v0.57. Old command encodings and retired
tile selectors are illegal. Toolchains must consume the v0.58 generated
catalog and codecs; no old decode is part of the v0.58 architecture.

## Implementation references

LinxCore implementation contracts are published under
`docs/architecture/linxcore/`. They may retain their own implementation
baseline labels, but they do not override this v0.58 ISA contract.

# v0.59.1 规范修订与版本身份

本次修订仅更新 LinxISA v0.59.1。基线是原签名标签指向的提交 `d262515b55c727073997c8f4c95261909f2fe8d3`。修改的兼容性单位是编码形式及其可执行行为。由可执行改为保留并拒绝属于不兼容变更，即使其余机器字和助记符完全相同。

## 维护依据

| 来源 | 对本次修订的含义 |
| --- | --- |
| RISC-V 非特权规范 §36.1.10 | 扩展版本用来传达指令语义的兼容性。它把兼容的次版本与失去兼容性的主版本区别开。本次撤下可执行机器字必须明确列为硬断开。Linx 沿用自己的编号规则。 |
| Semantic Versioning 2.0.0，第 3、4 条 | 0.y.z 可以处于初期演进阶段；采用 SemVer 时，已发布的特定版本内容仍应可复现。0.59.1 是用户指定的 ISA 版本号，修订身份和内容指纹需要另行记录。 |
| Git 的公开标签维护说明 | 已经抓取某个标签的使用者与新克隆者可能得到不同对象。保留可校验的旧提交和新修订提交，可以准确区分下载物。 |
| PTO ADR-GOV-0015 | PTO 明确区分架构版本 0.59.1、第一次发布 0.59.1.0 和共享编码 ABI。本次不修改 PTO 所有的定义或给预留空间分配指令。 |

## 兼容性判断

- 公开基线的 1,499 个编码形式减去明确裁决的 193 个，当前集合应为 1,306 个。对保留的 578 个共同形式、705 个作用域形式及 23 个 Linx 形式逐 ID 比较汇编、固定位、字段、约束和语义。
- 正向目录与反向译码要分别验证。目录中移除助记符后，还需验证各个 16/32 位块入口和整个 64 位 V.* 预留空间都不会落入其他译码分支。仅检查 193 个代表字不足以证明通配编码区域受保护。
- 固定的 PTO 提交、共享编码 ABI 和投影摘要只标识共同集合。已有程序若含这批 Linx 专用机器字，在修订版上会遇到拒绝；不能用相同的 PTO ELF note 推导出所有 Linx 二进制向后兼容。
- 发布说明、规范清单、Sail 导出与 HTML 应引用同一版目录及其 SHA-256，并列出本次实际验证范围。v0.57、v0.58 的目录、编码表、平台默认路径和行为独立保留。

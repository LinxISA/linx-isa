# LinxISA v0.59.2 设计延续性核对

核对基线为签名标签 v0.59.1 与 v0.59.2，以及两版共同锁定的 PTO 提交 `a89a53d48f57`。每项判断区分编码、行为、软件可见状态和实现选择。正文采用能够由本版证据确认的设计；仅有名称相同或来源年代较早，都不足以判定该设计的去留。

## 发布差异与影响

- 按 form ID 对比全部 1,499 条记录。除新增的架构状态外，汇编、固定位、字段、约束及原有语义记录逐项相同。193 个编码形式标为 obsolete，19 个 Linx 形式继续保留，4 个仅预留编码。另有 1,283 个 PTO 共有形式。
- 两版的标量、块命令、Tile、SSR、扩展预留、硬件数值符合性配置与数值向量共七份输入逐字节相同。保留项可沿已有定义查证；从 v0.58 或更早文档引用的具体位号、类型和操作仍需核对。[机器目录](https://github.com/LinxISA/linx-isa/blob/830fbdb53bccec889414b5673ffba31b0a08606d/isa/v0.59.2/linxisa-v0.59.2.json) · [编码状态裁决](https://github.com/LinxISA/linx-isa/blob/830fbdb53bccec889414b5673ffba31b0a08606d/docs/zh/architecture/linx-two-level-block-obsolescence.md)
- 谓词设计须区分三个层面：PTO 状态模型定义 P0–P7，但该模型明确没有直接消费这组寄存器的指令编码；RowMajor 打包谓词、CUBE PredicateCell 和 GPR 掩码仍有具体 Tile 消费者；Linx 二级执行模型的 lane 状态另有其模型用途。编码裁决没有给所有相关状态新增硬件禁令。[谓词状态](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/arch/programming-model/predicate-registers.asl) · [TCMP](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/tile/elementwise-tile-tile/logical/TCMP.asl)
- 汇编备注另外逐条比对：38 个基础整数和 15 个长立即数形式保留可执行于 Tile 标量块体的规则；16 个压缩形式保留 16 位编码说明；4 个 MIN/MAX 形式按整数比较与适用性规则修正。没有将旧页里的可选扩展开关或‘只能在浮点块执行’推广成全局限制。[标量块体入口](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/scalar/model/dispatch/top-level.asl) · [适用性检查](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/scalar/model/sys/semantics.asl)

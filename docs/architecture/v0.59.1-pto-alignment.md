# PTO 0.59.1 adoption for LinxISA

The LinxISA `v0.59` specification pins the published PTO ISA `v0.59.1.0` source in
`isa/v0.59/pto-spec.lock.json`. The source commit is
`a89a53d48f5708328be609fe2e6296ac8bdb4bc2` and its ABI is
`pto-isa-0.59.1-mode-function-v1`. The [LinxISA v0.58 contract](v0.58-architecture-contract.md)
governs the current superproject and its component pins for platform bring-up.
[PTO publication and signed tag](https://github.com/PTO-ISA/pto-spec/releases/tag/v0.59.1.0)

## Encoding changes

The import contains 473 unqualified Scalar forms, 705 scoped Scalar forms, 105
command forms, 119 direct Tile operations, 50 extension reservations, and 100
system-register definitions. Regenerate it from the pinned checkout with
`tools/isa/import_pto_v0591.py`.

The generated `isa/v0.59/pto-v0591-candidate.json` records the compiled common
bindings and scoped decode contracts for review. Run
`python3 tools/isa/build_pto_v0591_candidate.py --check` to verify the snapshot.

The 578 previously bound Scalar and command forms retain their effective
mask/match, spelling, and operand bit layout. The published `B.DATR` domain adds
`CMode` values 6 and 7. The published `BSTART.TMOV` domain adds raw `DataType`
values 15 and 21. The 705 new 64-bit envelopes occupy an encoding space disjoint
from the 194 64-bit Linx forms in the v0.58 comparison catalog. The alignment check compares the source IDs,
effective encodings, operands, constraint domains, and retained reservation rows.
[PTO compatibility boundary](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/docs/status/decisions/ADR-GOV-0015-0590-0-to-0591-compatibility.md)

## Sail and launch registers

The existing Linx register contract assigns `0x0050` and `0x0051` to the
read-only `BLOCKNUM` and `BLOCKID` registers. Sail uses that address map and a
zero ambient reset value. Block-local dimensions remain internal state selected
by the existing block instructions. The old `0x0052` through `0x0055` aliases
are reserved.

The published PTO launch protocol gives the admitted ACR0 worker its own logical
geometry until matching DONE or invocation cleanup. Sail models Message Buffer
banks, claim/ACK state, BSE admission and replay, and READY/LAUNCH/DONE. Its
directed tests exercise the encoded SSR and BSE/BWE paths with a bound platform
context. The embedding platform supplies the live invocation and recovery state.

All 705 scoped carriers exercise Sail's request and completion path. The model
captures scope and outer TPC, retains blocked requests, discards pending effects
on a fault, and retires successful carriers by eight bytes. The platform owns memory ordering,
paired access checks, atomic effects, reservation state, and queue synchronization
with other instruction paths.
[PTO HSCB launch contract](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/arch/state/hscb-dispatch.asl)
· [PTO scoped Scalar contract](https://github.com/PTO-ISA/pto-spec/blob/a89a53d48f5708328be609fe2e6296ac8bdb4bc2/asl/scalar/model/dispatch/top-level.asl)

## Scoped Scalar reference comparison

Run the candidate memory comparison with LLVM, LLD, QEMU and linx-model builds
that support the opt-in PTO 0.59.1 paths.

```bash
python3 tools/bringup/check_pto_v0591_scalar_reference.py \
  --llvm-bin "$LLVM_BUILD/bin" \
  --qemu "$QEMU_BUILD/qemu-system-linx64" \
  --linx-model "$LINX_MODEL_BUILD/linx_model_cli" \
  --gfrun "$LINX_CORE_MODEL/bin/gfrun" \
  --gfsim "$LINX_CORE_MODEL/bin/gfsim" \
  --output out/pto-v0591-scalar-reference
```

The script verifies the ELF identity and runs the same ELF on single-PE QEMU,
the linx-model reference engine, and any supplied LinxCoreModel binaries. Each
model must finish at the pass finisher and export 1,440 bytes for the 180
immediate/PCR carriers. The script compares each result to independent
catalog-based golden bytes and compares all model pairs. Omit `--gfrun` and
`--gfsim` for the two-model diagnostic. With `--symbolic-pcr`, the assembler must
emit all 66 PCR relocations at their 64-bit carrier start offsets. LLD writes the
inner PCR fields, and the four-model comparison uses the same golden bytes.
`provenance.json` records binary hashes,
the ELF hash and source revisions. `compare.json` identifies execution failures
and the first mismatching form. For release evidence, build the binaries in the
superproject's pinned checkouts and pass `--require-pinned`. The script verifies
that LinxISA and all four model inputs match clean checkouts at the recorded
gitlinks. Use the distinct LinxCoreModel `bin/gfrun` and `bin/gfsim` executables.
The release build must generate each binary from those pins before the run.
Integrated system qualification also requires multicore
execution, MSGB/HSCB host integration and the pinned LinxCoreModel gates.

## Specification release and platform qualification

Select the published specification with `python3 tools/isa/select_linxisa_profile.py --profile v0.59`. The platform default remains v0.58. The release package binds the catalog, upstream lock, transitive Sail sources and toolchain. Export the model with `python3 tools/isa/export_linxisa_v0591_sail.py --output /tmp/linxisa-v0591-sail` and use the entry `model/linxisa_v0591.sail`. Full-system promotion requires clean evidence on the final component pins. [Release scope, checks and open gaps](../releases/v0.59.1.md)

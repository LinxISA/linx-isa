== Tile / Vector Block Instructions (v0.58)

This chapter defines the **normative header contracts** for tile/vector/tensor-style block types in the live v0.58
profile.

It complements:

* <<blockisa-forms>> (block forms, coupled vs decoupled vs template),
* <<memory>> (architectural memory model + ordering), and
* the opcode catalog notes (e.g. `isa/v0.58/opcodes/lx_32.opc`).

Unless stated otherwise:

* These blocks do **not** use a coupled SIMT body like scalar blocks.
* Successor selection is **fallthrough** to the next block start marker in the linear stream (branch/target fields, if
  present, are ignored).
* Missing/invalid fallthrough markers are CFI violations (`E_BLOCK(EC_CFI)`), see System/Privilege trap reporting.

[[tileblocks-descriptors]]
=== Descriptor families (recap)

Tile/vector block headers use the standard descriptor families:

* `B.DIM`  — dimension/loop counters and/or operand extents
* `B.DATR` — operation-applicable datatype, layout, rounding, comparison, and pad/byte controls
* `B.IOR`  — absolute GPR bindings; TLOAD/TSTORE source 1 is byte row stride, while indexed TLSU source 1 is element row stride
* `B.IOT` — Local tile binding; destination `SizeCode=1..10` means 128 B through 64 KiB per participating PE
* `B.IOS` — Shared S0..S63 binding; destination `SizeCode=1..12` means 128 B through 256 KiB for the complete Core-wide object
* `B.TEXT` — body pointer for SIMT vector blocks (group-granular kernel body)

[[tileblocks-vvec]]
=== SIMT vector blocks (`VPAR`/`VSEQ`, `MPAR`/`MSEQ`)

These blocks execute a SIMT-style body:

* The body is a **group-granular kernel body**.
* Each group executes the body under one group PC and one EXEC mask `p`.
* Divergence inside the body is group-internal and expressed by explicit `p`
  updates.

Mandatory header descriptors:

* `B.DIM` is **mandatory** (sets up loop counters / extents).
* `B.TEXT` is **mandatory** and MUST point to a valid vector body.
  - The `B.TEXT` target is an engine-internal entrypoint and need not begin with a block start marker.
  - Alignment: `B.TEXT` targets MUST be 2-byte aligned. Misalignment MUST raise `E_BLOCK(EC_BFETCH)` with `TRAPARG0` set
    to the misaligned body-fetch address; this fault is **fatal** (non-restartable), see System/Privilege trap semantics.
  - Any *architectural* control-flow transfer to a `B.TEXT` target is illegal and MUST trap with `E_BLOCK(EC_CFI)` (kind `CFI_BAD_TARGET`).

Vector body termination:

* Valid body terminators are `BSTOP`/`C.BSTOP` and `BSTART.*`/`C.BSTART.*`.
* A terminator ends the current body execution only when control reaches that
  terminator.
* An earlier lexical terminator does **not** truncate the body if group-local
  control flow branches to a later label within the same out-of-line `B.TEXT`
  body.
* In-body control-flow targets remain group-internal and MUST stay within the
  current body region selected by `B.TEXT`.

If a mandatory descriptor is missing, hardware MUST trap with `E_BLOCK(EC_BLOCKFMT)` and report the missing descriptor family in `TRAPARG0` (see System/Privilege trap reporting).

MissingDescFamily numeric IDs (from `TRAPARG0[7:0]`, for quick reference):

* `0 = B.* (generic descriptor stream / non-family-specific)`
* `1 = B.DIM`
* `2 = B.TEXT`
* `3 = B.CATR/B.DATR`
* `4 = B.IOR`
* `5 = B.IOT`
Other descriptors (tile inputs, register in/out bindings, etc.) are kernel-defined and may be mandatory for specific
kernels but are not universally required by the ISA.

[[tileblocks-rendering-profile]]
=== Rendering profile (v0.58 canonical)

The rendering-oriented v0.58 profile inherits the frozen v0.58 tile conventions unless a v0.58 delta explicitly changes them:

* tiles remain general-purpose intermediate-state storage; they are not inherently screen-space tiles,
* the canonical carrier is a 4KB `1024x1` row-major tile,
* fragment and hot-state transport is SoA-oriented,
* TAU operations are tile-to-tile only,
* small or rarely-changing state is descriptor-driven (`B.DATR`, `B.DIM`, `B.IOR`), while hot/large state uses dedicated StateTiles,
* `MPAR` VEC kernels are the required functional fallback for rendering PTOs when no TAU hardening exists.

[[tileblocks-tlsu]]
=== Tile load/store unit blocks (`TLOAD`/`TSTORE`)

`BSTART.TLOAD` / `BSTART.TSTORE` are the named forms for TLSU Functions 0/1.

These blocks do not have a SIMT body (`B.TEXT` is not used).

Mandatory header descriptors:

* `B.DATR` is required when the operation uses non-default layout/pad controls.
* `B.IOR` is optional. If omitted, base is zero and row stride is the dense
  column count; an explicitly encoded zero stride is not replaced by a default.
* Local form: `B.IOT` is mandatory for Local tile binding and tile size.
* Shared form: `B.IOS` is mandatory for the Shared register and PE mask;
  `B.IOT` is not legal as a Shared-mask companion.

Missing mandatory descriptors MUST trap with `E_BLOCK(EC_BLOCKFMT)` and report the missing descriptor family in `TRAPARG0` (see System/Privilege trap reporting).
[[tileblocks-tmov]]
=== Tile move / reshape blocks (`TMOV`)

NOTE (header legality): `B.TEXT` is not meaningful for header-driven engine ops (`TMOV`/`TLSU`/`CUBE`/`VEC`/`SFU`). If `B.TEXT` appears in such a header, it is an illegal descriptor combination and MUST trap with `E_BLOCK(EC_BLOCKFMT)` with `MissingDescFamily=B.TEXT` and `MissingDetail=0x02`.

`BSTART.TMOV` is the named form for TLSU Function 2.

`TMOV` is tile-state only (no global memory access). Destination allocation is queue-push only.

Mandatory header descriptors:

* `B.IOT` is **mandatory** (bind source/destination tiles and tile sizes).

Optional descriptors:

* `B.DATR` selects an operation-applicable layout conversion; NORM is the mandatory default and other layouts are capability gated.

[[tileblocks-cube]]
=== CUBE / tensor blocks

`BSTART.TMATMUL*`, `BSTART.TMATMULMX*`, `BSTART.TGEMV*`, and
`BSTART.TGEMVMX*` are the named CUBE-family forms in the frozen 0.58 selector
map; no generic executable `BSTART.CUBE` form exists. `ACCCVT` is deleted from
the 0.58 direct-operation catalog and MUST NOT decode.

These blocks do not have a SIMT body (`B.TEXT` is not used).

==== `TMATMUL` / `TMATMUL.ACC`

Mandatory header descriptors:

* `B.DIM` is **mandatory** and specifies `m/n/k` via `LB0/LB1/LB2`.
* `B.IOT` is **mandatory** (bind operand tiles and sizes).
* `B.DATR` is required when a non-default, supported matrix layout is selected.

Every CUBE form has an explicit destination. An `.ACC` form additionally has
an explicit accumulator source; the other forms do not read an accumulator.
If destination and accumulator alias the same allocation, the operation reads
the old accumulator value before writing the new result, and their data type,
shape, layout, and allocation must be identical.
